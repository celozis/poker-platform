# ADR-0004: Структура блайндов — JSONB в строке турнира, шаблоны лиги — в коде

## Status

Accepted

## Context

У турнира есть структура блайндов: уровни (малый и большой блайнд, анте, длительность) и перерывы между ними, в порядке игры. Администратор выбирает шаблон лиги и правит его под конкретный турнир: меняет, добавляет и удаляет уровни, вставляет перерывы. Спек #1 в MVP разрешает только общие шаблоны лиги («Custom blind структуры: только league-wide defaults»).

Нужно решить две вещи:

1. **Где хранить структуру турнира.** Варианты: отдельная таблица `blind_levels` (строка на уровень, с `tournament_id`, номером и по ADR-0003 с `club_id`) или колонка JSONB в строке турнира.
2. **Где хранить шаблоны лиги.** Варианты: таблица в базе (заполняется миграцией или сидом) или константы в коде backend.

## Decision

1. **Структура хранится в колонке `tournaments.structure` (JSONB)**: список элементов `{"kind": "level", small_blind, big_blind, ante, duration_minutes}` и `{"kind": "break", duration_minutes}`. Форму элемента задаёт `StructureItem` в `app/schemas.py`, правила — `app/tournament_rules.py`.
   - Структура всегда читается и сохраняется целиком, вместе с турниром. Отдельно уровни никто не запрашивает.
   - Номер уровня не хранится: он получается из порядка в списке, перерывы не нумеруются. Поэтому вставка и удаление не требуют перенумерации строк.
   - Структура — часть турнира, поэтому изоляцию по клубу даёт `club_id` самого турнира (ADR-0003). Отдельная таблица потребовала бы ещё одного `club_id`.
2. **Шаблоны лиги — константы в `app/blind_templates.py`**, отдаются вошедшему администратору через `GET /api/blind-templates`. Турнир хранит свою копию структуры, поэтому изменение шаблона не меняет уже созданные турниры.

Решение по шаблонам принято вместе с заказчиком при реализации тикета #4.

## Consequences

- Плюс: одна строка на турнир, сохранение структуры — одна запись, без синхронизации дочерних строк.
- Плюс: новые шаблоны лиги добавляются правкой одного файла, без миграций.
- Минус: база не проверяет содержимое JSONB. Корректность держится на `TournamentIn`/`tournament_rules.py`, в обход API в колонку можно записать что угодно.
- Минус: запросы «по уровням» (например, отчёт по средней длительности уровня по всем турнирам) придётся писать через функции JSONB.
- Минус: менять шаблоны может только разработчик через релиз.
- Пересмотреть, когда владелец сети должен будет сам редактировать шаблоны (история №43 спека #1): тогда шаблоны переезжают в таблицу, а структура турнира остаётся в JSONB. Если движку турнира (таймер блайндов) понадобится хранить состояние по уровням (фактическое время начала и т. п.), это отдельные данные о ходе турнира, а не часть структуры.
