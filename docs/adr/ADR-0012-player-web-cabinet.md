# ADR-0012: Веб-кабинет игрока — свой вход по коду и данные только из сессии

## Status

Accepted

## Context

Тикет #12: игрок входит на сайт по номеру телефона и одноразовому коду, как администраторы (ADR-0003, тикет #2), и видит свои данные: профиль, место и очки в рейтинге клуба за сезон, историю турниров, ближайшие турниры клуба. Игрок видит только свои данные, и запрос чужих данных через API получает отказ.

Нужно было решить:

1. **Как устроен вход игрока** рядом со входом администратора. Один человек может быть и администратором, и игроком с тем же телефоном.
2. **Как отдавать данные** так, чтобы чужие нельзя было запросить.
3. **Какие клубы показывать.** Игрок один на лигу и может быть в списках нескольких клубов (ADR-0005). В боте у него один выбранный клуб, а в кабинете клубов может быть несколько.
4. **Где на сайте кабинет.**

## Decision

1. **Тот же механизм, отдельный вход.** Отправка и проверка кода (5 минут, 5 попыток, не чаще раза в минуту, код в логе) и создание токена сессии вынесены в общие функции `app/auth.py` (`send_login_code`, `take_login_code`, `new_session_token`). Их вызывают и `/api/auth/...` администратора, и `/api/cabinet/...` игрока. У кода входа появилось **назначение** (`login_codes.purpose`: `admin` или `cabinet`, часть первичного ключа, миграция 0011). Поэтому код, отправленный в админ-панель, не открывает кабинет, а код кабинета не открывает админ-панель, даже если это один человек. Код получает любой игрок, которого знает лига (телефон есть в `players`). На незнакомый номер ответ тот же, но кода нет, как у администраторов.
2. **Сессия игрока — своя таблица `player_sessions` и своя cookie `player_session`**, выданная только на путь `/api/cabinet`. Зависимость `CurrentPlayer` читает только её. Админские адреса по ней не открываются (401), кабинет по cookie администратора тоже не открывается (401).
3. **Кабинет не принимает id игрока.** `GET /api/cabinet` отдаёт всё сразу для игрока из сессии, поэтому подставить чужой id некуда. Рейтинг клуба считает та же `club_standings` (ADR-0008), но в ответ попадает только строка самого игрока: чужих имён кабинет не показывает.
4. **Все клубы игрока** (решение заказчика при реализации тикета): рейтинг за текущий сезон и ближайшие турниры для каждого клуба, в списке которого игрок числится (`club_players`), в порядке, в котором он в них попал. История — по всем клубам лиги, с названием клуба.
5. **Ближайшие турниры — то же расписание, что в боте.** Выборка вынесена из бота в `app/schedule.py` (`club_schedule`): не начатые и не отменённые (до закрытия отметки прихода через 12 часов после начала), а также идущие, пока открыта поздняя регистрация; 10 ближайших. Для каждого указано, записан ли игрок. Записываться в кабинете нельзя: это делается в боте и у администратора.
6. **История** — завершённые турниры, где у игрока есть место: дата, турнир, клуб, место из скольких (игроки считаются по одному разу, ADR-0008), очки, число re-entry и add-on. Денег в истории нет (решение заказчика): только количества.
7. **Кабинет открывается на корне сайта** (решение заказчика): это адрес, который дают игрокам. Админ-панель переехала на `/admin`, табло осталось на `/board/<код>`.

## Consequences

- Плюс: изоляция данных игрока держится на одной зависимости `CurrentPlayer` и на том, что в адресах кабинета нет id. Тесты (`backend/tests/test_cabinet.py`): без входа 401; сессия администратора не открывает кабинет; сессия игрока не открывает клубные данные админ-панели; код админ-панели не открывает кабинет; после выхода старая cookie бесполезна.
- Плюс: бот и кабинет показывают одно и то же расписание; правило поменяется в одном месте.
- Минус: `GET /api/cabinet` считает рейтинг каждого клуба игрока целиком, чтобы найти одну строку. Для 2–3 клубов это дёшево. Если станет медленно, `club_standings` можно сузить до одного игрока (оконная функция `RANK()`).
- Минус: сессия игрока живёт 7 дней, как у администратора. С телефона придётся входить раз в неделю. Если игроки попросят, срок можно увеличить отдельно для кабинета.
- Минус: старые закладки администраторов на корень сайта теперь ведут в кабинет игрока. Администраторам нужен новый адрес `/admin`.
- Вход через VK или Telegram, правка профиля и запись на турнир из кабинета остаются на потом.
