## Краткий итог

Администратор клуба ведёт базу игроков и записывает их на турниры. Он может:

- завести игрока: имя, телефон и отметка о согласии на обработку персональных данных (152-ФЗ). Без согласия игрок не создаётся;
- ввести телефон, который уже есть в лиге. Дубль при этом не создаётся: существующий игрок попадает в список клуба под своим прежним именем, и админ видит сообщение об этом;
- искать игроков своего клуба по имени или телефону. Телефон можно набирать как угодно, например «8 913 555» или «111-00-03»;
- открыть турнир (кнопка **«Регистрации»** в списке турниров) и увидеть зарегистрированных со статусом «Зарегистрирован» или «Пришёл»;
- записать игрока на предстоящий турнир: найти поиском или сразу завести нового кнопкой «Новый игрок» → «Добавить и зарегистрировать»;
- снять игрока с регистрации;
- отметить приход (check-in) в день турнира и отменить ошибочную отметку.

Игрок один на всю лигу, у каждого клуба свой список игроков. Админ одного клуба не видит ни игроков, ни регистраций другого.

Критерии приёмки из тикета:

| Критерий | Статус | Как проверено |
|---|---|---|
| Администратор создаёт игрока: имя, телефон, отметка о согласии. Без согласия игрок не создаётся | ✅ | Backend-тесты: создание, отказ без согласия, отказ при пустом имени и неверном телефоне. Frontend-тесты: форма с согласием и без. Вживую через API |
| Повторный ввод существующего в лиге телефона не создаёт дубль, а подтягивает игрока в клуб | ✅ | Backend-тест: второй клуб вводит тот же телефон в другом написании и с другим именем. | Поиск игрока по имени или телефону | ✅ | Backend-тест: регистр букв, часть имени, телефон с 8 и без, пустой запрос, спецсимволы, одиночная «8». Игрок чужого клуба не находится. Frontend-тест |

| На странице турнира виден список зарегистрированных со статусом | ✅ | Frontend-тесты: статусы «Зарегистрирован» и «Пришёл», счётчик «Зарегистрировано: N, пришли: M». Отдельно проверено, что у закрытого турнира кнопок нет |

## Как этим пользоваться

```bash
docker compose up --build                          # поднять всё; миграция 0004 применится сама
docker compose exec backend python -m app.seed     # тестовые клубы и админы (если ещё не создавали)
```

Если стек уже запущен со старым кодом, достаточно `docker compose restart backend`. В логе должно появиться `Running upgrade 0003 -> 0004`. Новых npm-пакетов нет.

1. Войдите, как раньше: `+7 999 000-00-01` (клуб «Обь») или `+7 999 000-00-02` (клуб «Енисей»). Код смотрите командой `docker compose logs backend | grep "Код входа"`.
2. Под шапкой появились вкладки **«Турниры»** и **«Игроки»**.
3. **«Игроки»** → форма «Новый игрок»: имя, телефон в любом виде (`8 913 555-12-34`, `+7 913 5551234`), галочка «Игрок согласен на обработку персональных данных». Кнопка **«Добавить игрока»**. Без галочки появится красный блок «Игрок не добавлен: Без согласия…».
4. Ниже список «Игроки клуба» с полем поиска по имени или телефону.
5. **Проверка «нет дублей»:** выйдите, войдите за «Енисей» и введите телефон игрока «Оби» с любым именем. Появится зелёное сообщение «Игрок … уже есть в лиге и теперь добавлен в ваш клуб». Имя останется тем, под которым игрока завела «Обь».
6. **«Турниры»** → у любого турнира кнопка **«Регистрации»**. Откроется страница турнира:
   - блок **«Записать игрока»** (только пока турнир не начался и не отменён): поле «Имя или телефон игрока клуба», в найденных кнопка **«Зарегистрировать»**. Кнопка **«Новый игрок»** открывает форму, которая заводит игрока и сразу записывает его;
   - блок **«Зарегистрированные»**: счётчик, у каждого игрока статус, кнопки **«Отметить приход»** / **«Отменить приход»** (с 12 часов до начала до 12 часов после начала) и **«Снять с регистрации»** (до начала турнира);
   - **«Назад к списку»** возвращает к турнирам.
7. Чтобы показать check-in на видео, создайте турнир, который начнётся в ближайшие 12 часов. Для турнира через неделю отметка прихода ещё закрыта, и под заголовком будет подсказка про окно.

### Адреса API

Все адреса клубные и проходят через `AdminClub` (ADR-0003). Во всех случаях: **401** без входа, **403** «Нет доступа к этому клубу» для чужого клуба.

| Метод и адрес | Что делает | Ответы |
|---|---|---|
| `GET /api/clubs/{club_id}/players?q=…` | игроки клуба по имени; `q` ищет по части имени без учёта регистра или по цифрам телефона | **200** `[{id, name, phone}]` |
| `POST /api/clubs/{club_id}/players` | `{name, phone, consent}` | **201** `{player, outcome: "created"}`; **200** `{player, outcome: "added_to_club" \| "already_in_club"}`; **422** список причин |
| `GET …/tournaments/{id}/registrations` | `{registration_open, check_in_open, registrations: [{player, status}]}`, по имени | **200**, **404** «Турнир не найден» |
| `POST …/tournaments/{id}/registrations` | `{player_id}` | **201** `{player, status}`; **404** «Игрок не найден в клубе»; **409** «… уже зарегистрирован на этот турнир» / «Турнир уже начался, регистрация закрыта» / «Турнир отменён, регистрация закрыта» |
| `DELETE …/registrations/{player_id}` | снять с регистрации | **204**; **404** «Игрок не зарегистрирован на этот турнир»; **409** как выше |
| `POST …/registrations/{player_id}/check-in` | отметить приход (повторно — без изменений) | **200** `{player, status: "checked_in"}`; **409** «Отметка о приходе откроется за 12 часов до начала турнира» / «Отметка о приходе закрыта: турнир начался больше 12 часов назад» / «Турнир отменён» |
| `DELETE …/registrations/{player_id}/check-in` | отменить ошибочную отметку | **200** `{player, status: "registered"}`; **409** как выше |

### Правила

| Правило | Где |
|---|---|
| Имя не пустое и не длиннее 200 символов; телефон — российский номер из 11 цифр (8… или +7…); согласие отмечено. Все нарушения перечисляются сразу | `_player_errors()` в `app/players.py` |
| Одна запись на телефон в лиге. Известный телефон добавляет существующего игрока в клуб, имя не меняется | `add_player()`: `INSERT … ON CONFLICT DO NOTHING` |
| Поиск: часть имени (`ILIKE`, спецсимволы `%` и `_` экранируются) или цифры телефона. Ведущая 8 читается как +7, если набрано хотя бы 4 цифры | `_matching()` в `app/players.py` |
| Записать или снять можно, пока турнир не начался и не отменён | `_registration_closed_because()` в `app/registrations.py` |
| Отметить приход или отменить отметку можно с 12 ч до начала по 12 ч после начала (границы включительно), и не для отменённого турнира | `_check_in_closed_because()`, константа `CHECK_IN_HOURS` |
| Записать можно только игрока из списка своего клуба | `_club_player()` |

## Ход работы по шагам

### Шаг 1. Изучение задачи и окружения

⚠️ Мелочь: команда `gh issue view 5` без `--repo` на этой машине молча ничего не выводила, видимо из-за кириллицы в пути к папке. С явным `--repo celozis/poker-platform` сработало.

Исходная точка: 38 backend-тестов зелёные, Docker-стек запущен.

### Шаг 2. Решения, принятые с вами до начала работы

1. **Когда можно отмечать check-in.** В тикете сказано «в день турнира», но у клубов нет часового пояса, а «турнир начался» у нас значит «наступило время начала». Были варианты: окно ±12 ч, календарный день по часам клуба (с новым полем «часовой пояс» у клуба) или без ограничений. **Выбрано окно: с 12 часов до начала до 12 часов после начала.** Для вечернего турнира это весь его день плюс ночь, и опоздавших можно отметить после начала.
2. **Где искать игроков.** **Выбрано: только среди игроков своего клуба.** Игрока из другого клуба админ подтягивает, вводя его полный телефон в форме нового игрока. Имена чужих игроков поиск не показывает (152-ФЗ).
3. **Швы для тестов** — как в тикете #4: backend через HTTP API (`TestClient` против настоящего PostgreSQL), frontend через всё приложение `<App/>` с фальшивым backend.

Решения, которые я принял сам и которые стоит знать:

- **Регистрация и её отмена — только до начала турнира и не для отменённого.** В тикете сказано «на предстоящий турнир». Поздняя регистрация (запись после начала) относится к движку турнира.
- **Отмена ошибочной отметки прихода.** В тикете её нет, но без неё случайный клик не исправить: снять игрока и записать заново после начала турнира уже нельзя.
- **Согласие требуется при каждом добавлении**, в том числе когда игрок уже есть в лиге: согласие собирает клуб, куда пришёл человек. При этом хранится только время первого согласия (см. «Известные ограничения»).
- **При повторном телефоне имя не перезаписывается.** Админ видит, под каким именем игрок уже известен.

### Шаг 3. Backend, циклы 1–4: игроки

Работа шла по TDD: тест, потом минимальный код.

1. «Админ добавляет игрока и видит его в списке клуба». Красный (404), затем модели `Player` и `ClubPlayer`, миграция `0004`, роутер `app/players.py`. Телефон нормализуется той же `normalize_phone()`, что при входе админа.
2. «Без согласия не создаётся» и «нужны имя и российский телефон». Правила собраны в `_player_errors()`, все нарушения возвращаются одним списком, как у турниров.
3. «Повторный телефон подтягивает игрока, а не создаёт дубль». Сделано через `INSERT … ON CONFLICT DO NOTHING RETURNING`. Так дубль не возникнет, даже если два админа одновременно введут один телефон: второй запрос дождётся первого и найдёт уже созданного игрока. Результат (`created` / `added_to_club` / `already_in_club`) вычисляется по тому, вставилась ли строка в `players` и в `club_players`.
4. «Поиск по имени или телефону». Проверил, что `ILIKE` в нашем PostgreSQL (образ `postgres:16-alpine`) сравнивает кириллицу без учёта регистра: «иван» находит «Иван Петров» и «Мария Иванова». Тест это закрепляет. Цифры из запроса ищутся в телефоне, а «8 913 …» дополнительно читается как начало «+7 913 …». Символы `%` и `_` экранируются, чтобы «%» не находил всех.
   - Мелкая правка по ходу: mypy не принял наращивание условия через `|=`, переписал на список условий и `or_()`.

Тип `Outcome` переименовал в `AddPlayerOutcome`: одно слово «Outcome» в `schemas.py` ни о чём не говорило.

### Шаг 4. Backend, цикл 5: изоляция клубов для игроков

Тесты на 403 (чужой клуб не видит и не добавляет игроков) и 401 (без входа). Они прошли сразу: доступ даёт `AdminClub`. Проверку того, что тесты ловят утечку, делал позже, в шаге 7.

### Шаг 5. ⚠️ Проблема: тестовая база «застряла» на черновой миграции

Сначала миграция `0004` создавала только `players` и `club_players`. Когда я добавил в неё `registrations`, тесты упали с `table "registrations" does not exist`. Причина: тестовая фикстура перед прогоном откатывает базу до нуля, а откат новой версии `0004` пытался удалить таблицу, которой в базе ещё не было.

Решение: сбросил схему **только тестовой базы** `poker_test`:
`docker compose exec -T db psql -U poker -d poker_test -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"`.
Dev-базу `poker` это не затронуло: к ней миграция применилась один раз, уже в финальном виде (шаг 12).

**Если такое повторится** после правки ещё не выпущенной миграции, помогает та же команда.

### Шаг 6. Backend, циклы 6–10: регистрации и check-in

1. «Админ записывает игроков клуба на предстоящий турнир». Модель `Registration` с `club_id` (ADR-0003) и уникальной парой (турнир, игрок), роутер `app/registrations.py`. Функцию поиска турнира клуба из `tournaments.py` сделал общей: `club_tournament(..., for_update=True)` берёт турнир только своего клуба и блокирует строку.
2. «Дважды не записать» → 409 с именем игрока. Проверка безопасна при параллельных запросах, потому что строка турнира заблокирована. Уникальный индекс в базе — вторая страховка. «Игрок не из клуба» → 404.
3. «Регистрация только до начала и не для отменённого турнира», плюс флаг `registration_open` в ответе списка, чтобы интерфейс знал, показывать ли кнопки.
4. «Снятие с регистрации» (`DELETE …/{player_id}`): удаляет строку, после этого игрока можно записать снова.
5. «Check-in в окне ±12 ч» и флаг `check_in_open`. Тест двигает часы: за 31 ч до начала — отказ; ровно за 12 ч — можно; повторная отметка ничего не меняет; ровно через 12 ч после начала — можно; ещё через минуту — отказ. Отдельные тесты: отмена отметки, отменённый турнир.

### Шаг 7. Backend, цикл 11: изоляция клубов для регистраций

- получает 404, если подставить номер турнира «Оби» в адрес своего клуба;

### Шаг 9. Frontend: раздел «Игроки»

## Известные ограничения и открытые вопросы

1. **Согласие хранится один раз на игрока** (время первого согласия). Если юрист скажет, что каждый клуб — отдельный оператор данных и должен хранить своё согласие, время согласия переедет в `club_players` (ADR-0005). **Вопрос к заказчику.**
2. **Имя игрока нельзя исправить.** Имя задаёт клуб, который завёл игрока первым. Правки профиля пока нет.
3. **Админ, знающий чужой телефон, может подтянуть игрока в свой клуб** и увидеть его имя. Для MVP это нормальный путь нового гостя. Защита на будущее — SMS-код игроку.
4. **Check-in — окно ±12 ч, а не календарный день.** Турнир, идущий за полночь, после 12 часов от начала отметить уже нельзя. Если появятся часовые пояса клубов, правило можно переделать.
5. **Поздней регистрации нет:** после начала турнира записать нельзя. Это часть будущего движка турнира.
6. **Удалить игрока из клуба или из лиги нельзя.** Для 152-ФЗ (отзыв согласия) это понадобится отдельной задачей.
7. **Список игроков клуба без постраничного вывода.** Для 2–3 клубов с сотнями игроков это не проблема. При тысячах игроков понадобится ограничение.
8. **Интерфейс не проверен в браузере** в этой сессии: только тестами и через API на живом стеке.
9. **Прежние хвосты** из тикетов #2–#4 (флаг `secure` у cookie, очистка старых кодов и сессий, ограничение частоты запросов, раздел «Deployment» в `CLAUDE.md`) остались как были.

## Если что-то сломалось: куда смотреть

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| `relation "players"` (или `club_players`, `registrations`) `does not exist` | Миграция `0004` не применилась | `docker compose restart backend` (или `up -d --build backend`), в логе должно быть `Running upgrade 0003 -> 0004` |
| Backend-тесты падают с `table "registrations" does not exist` на старте | Тестовая база осталась на старой версии миграции (шаг 5) | `docker compose exec -T db psql -U poker -d poker_test -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"` |
| Нет вкладки «Игроки» или кнопки «Регистрации» | Фронтенд со старым кодом или кэш браузера | Обновить страницу (Ctrl+F5), проверить `docker compose logs frontend` |
| «Без согласия на обработку персональных данных игрока завести нельзя» | Не отмечена галочка | Отметить галочку согласия |
| «Телефон: нужен российский номер из 11 цифр» | В номере не 11 цифр или он не начинается с 7/8 | Ввести номер полностью: `8 913 …` или `+7 913 …` |
| Ввели нового игрока, а в списке другое имя | Телефон уже есть в лиге, имя не перезаписывается (ADR-0005) | Так задумано, сообщение об этом показывается зелёным |
| Поиск не находит игрока, который точно есть в лиге | Поиск идёт только по своему клубу (решение из шага 2) | Ввести полный телефон в форме «Новый игрок», и игрок подтянется в клуб |
| Нет блока «Записать игрока» на странице турнира | Турнир начался или отменён (`registration_open = false`) | Так задумано |
| Нет кнопки «Отметить приход» | До начала больше 12 ч, или прошло больше 12 ч после начала, или турнир отменён | Подсказка под заголовком «Зарегистрированные». Часы сервера: `docker compose exec backend date -u` |
| «Игрок не найден в клубе» (404) при записи | Игрок не из списка этого клуба | Добавить его через форму нового игрока |
| «… уже зарегистрирован на этот турнир» (409) | Повторная запись | Так задумано |
| Сообщение вида «поле «x»: …» вместо русской подписи | Нового поля нет в `_FIELDS` | Добавить подпись в `app/validation_errors.py` |
| curl из Git Bash: 400 «There was an error parsing the body» | Кириллица в аргументах командной строки ушла не в UTF-8 | Тело запроса из UTF-8-файла (`--data-binary @file.json`) или Python |
| Список регистраций «прыгает» при быстрых кликах | Сломана защита от ответов не по порядку | Проверить `latestLoad` в `RegistrationsPage.tsx` и `current` в `usePlayerSearch.ts` |
