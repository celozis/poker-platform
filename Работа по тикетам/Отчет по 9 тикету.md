## Краткий итог

Появился **Telegram-бот лиги** (в прототипе — @pokerclub_test_bot). Он поднимается вместе со всем остальным через `docker compose up` отдельным сервисом `bot`. Разговор с игроком идёт по шагам:

1. **`/start`** — приветствие и просьба дать **согласие на обработку персональных данных** (кнопки «Согласен» / «Не согласен»). Без согласия бот дальше не пускает: на любые сообщения, команды и присланный контакт он снова просит согласие.
2. **«Поделиться контактом»** — кнопка внизу экрана. Telegram присылает номер, который он сам подтвердил.
   - Если игрок с этим телефоном уже есть в лиге (его завёл администратор), бот **привязывает Telegram к нему**: «Нашли вашу карточку игрока: Иван Петров. Telegram привязан к ней». Имя остаётся тем, что ввёл клуб.
   - Если телефона в лиге нет, бот **заводит нового игрока** с именем из Telegram.
3. **Выбор клуба** — кнопки со всеми клубами лиги («Покер-клуб «Енисей»», «Покер-клуб «Обь»»). Игрок попадает в **список игроков этого клуба** в админ-панели (ваше решение). Сменить клуб — команда **`/club`**.
4. **`/schedule`** — ближайшие турниры своего клуба (до 10), например:
   ```
   Покер-клуб «Обь», ближайшие турниры:
   пт 2 октября, 19:30 — Пятничный турнир, бай-ин 2 000 ₽
   вс 4 октября, 15:00 — Воскресный турнир, бай-ин 1 500 ₽
   ```

Повторный `/start` не заводит дублей. Бот узнаёт игрока: «Вы — Мария Иванова, ваш клуб: Покер-клуб «Обь». Расписание его турниров: /schedule».

## Как этим пользоваться

### Токен бота

Бот из прототипа уже создан в @BotFather (@pokerclub_test_bot), его токен лежит в файле `.env` в корне проекта:

```
TELEGRAM_BOT_TOKEN=<токен>
```

Файл `.env` в git не попадает (он в `.gitignore`). На другой машине этот файл нужно создать заново. Без токена сервис `bot` пишет в лог «Бот не запущен: нет токена…» и останавливается, остальное работает.

### Запуск

```bash
docker compose up -d --build                        # всё, включая бота; миграция 0009 применится сама
docker compose exec backend python -m app.seed      # тестовые клубы (если ещё не создавали)
docker compose logs -f bot                          # что делает бот
```

Появился новый pip-пакет **aiogram 3.31.0**, поэтому образ нужно пересобрать (`--build`). После правки кода бота: `docker compose restart bot`. Backend перезагружается сам, бот — нет.

### Сценарий для видео

1. Войдите в админку за «Обь» (`+7 999 000-00-01`, код: `docker compose logs backend | grep "Код входа"`).
2. **Турниры**: создайте 2–3 турнира на ближайшие дни с разным бай-ином. Один отмените, чтобы показать, что его нет в расписании.
3. **Игроки**: заведите игрока **с вашим номером телефона** и именем, например «Иван Петров (клуб)».
4. В Telegram откройте **@pokerclub_test_bot** → «Запустить» (`/start`).
   - Бот здоровается и просит согласие.
   - Нажмите «Не согласен» → «Без согласия… бот не может продолжить». Напишите `/start` снова.
5. Нажмите **«Согласен»** → внизу появится кнопка **«Поделиться контактом»** → нажмите её и подтвердите.
6. Бот: «Нашли вашу карточку игрока: Иван Петров (клуб). Telegram привязан к ней» — имя из админки, не из Telegram. Ниже кнопки клубов.
7. Нажмите **«Покер-клуб «Обь»»** → «Ваш клуб: … Расписание его турниров: /schedule».
8. **`/schedule`** → ваши турниры с датой, временем и бай-ином; отменённого нет.
9. В админке откройте **Игроки**: игрок на месте, дубля нет.
10. **`/start`** ещё раз → «Вы — Иван Петров (клуб), ваш клуб: …» — ни согласия, ни контакта заново.
11. (По желанию) **`/club`** → «Покер-клуб «Енисей»» → `/schedule` покажет турниры «Енисея» (или «пока нет запланированных турниров»).

Чтобы показать **нового** игрока: удалите игрока с вашим номером или используйте телефон, которого в базе нет. Бот скажет «Готово, вы в базе лиги: <имя из Telegram>», а игрок появится в списке выбранного клуба.

### Как части связаны между собой

```
Telegram ──(long polling)── app/bot/__main__.py
                                 │
                     telegram.create_dispatcher(clock)
                                 │  обработчик: /start, /schedule, /club, кнопки, контакт, прочее
                                 ▼
                     _run_step: поток → своя сессия → telegram_user(id) (строка залочена)
                                 │                 → шаг conversation.* → commit
                                 ▼
          conversation: current_step: согласие? → игрок? → клуб? → «готово»
                        share_contact ── players.league_player (один игрок на телефон)
                        choose_club   ── players.add_to_club_list (список клуба)
                        schedule      ── турниры клуба: scheduled, не позже 12 ч после начала, до 10
```

### Правила

- **Согласие** даёт сам игрок в боте, до всего остального. Время согласия хранится у Telegram-аккаунта. Если игрок новый, это время становится временем согласия игрока. Если игрока завёл клуб, у него остаётся согласие, собранное клубом.
- **Засчитывается только свой контакт.** Чужой контакт, присланный через «Вложение → Контакт», отклоняется: «Это чужой контакт. Отправьте свой номер…».
- **Только российские номера `+7`**, как в админке. Для другого номера бот советует обратиться к администратору клуба.
- **Один Telegram-аккаунт на игрока.** Если номер игрока подтвердил другой Telegram-аккаунт (человек сменил аккаунт), привязка переходит к новому. Старый аккаунт бот снова просит поделиться номером.
- **Выбор клуба** добавляет игрока в список игроков клуба. Если игрок с выбранным клубом привязался к другому игроку (сменился номер), тот тоже попадает в список клуба.
- **Расписание** включает турниры клуба, которые не начаты и не отменены, не больше 10 ближайших. Время показано по лиге (UTC+7, как у сезонов: у клубов пока нет своего часового пояса). Турнир, который администратор не начал и не отменил, остаётся в расписании до 12 часов после времени начала — пока открыта отметка прихода. Потом он пропадает.
- **Только личные чаты**: в группе бот молчит.
- **Текст без разметки** (без HTML): название турнира выводится как есть, спецсимволы в нём ничего не ломают.

### Шаг 3. Решения до начала работы

С вами (по `/tdd` швы тестов согласуются до первого теста):

- **Швы тестов**:
  1. **Бот через Telegram.** Настоящий диспетчер aiogram получает сымитированные сообщения и нажатия. Подставной Telegram — это адаптер на месте сессии бота aiogram — записывает, что бот отправил. База — настоящая тестовая PostgreSQL, часы — подставные.
  2. **Админ-API как свидетель.** Турниры для расписания создаются через API. Последствия работы бота (игрок заведён, дубля нет, игрок в списке клуба) видны через API списка игроков и добавления игрока, без запросов в базу.
- **Выбор клуба в боте добавляет игрока в список игроков клуба.**
- **Токен бота** — вы положили его в `.env`.

Решения по устройству (записаны в ADR-0010):
- бот — **отдельный сервис** `bot` из того же образа и кода, что backend, работает с базой через общий код;
- **long polling**;
- **состояние разговора в таблице `telegram_users`**, а не в памяти процесса — перезапуск бота ничего не теряет.

По `codebase-design`:
- Telegram — внешняя зависимость, у неё **два адаптера** (настоящая сессия aiogram и `FakeTelegram` в тестах), значит шов настоящий;
- база подменяется локальной тестовой PostgreSQL, без порта.

Мои решения по мелким вопросам правил (вы поручили такие мне):
1. **Повторный `/start` не спрашивает согласие и контакт заново**, а продолжает с первого несделанного шага. Спрашивать каждый раз было бы навязчиво, а согласие уже записано.
2. **«Забытый» турнир в расписании.** Турнир, который админ не начал и не отменил, показывается до 12 часов после начала, как открыта отметка прихода. Потом игрок прийти на него уже не может. В админке такой турнир остаётся в «предстоящих» сколь угодно долго: админу нужно его начать или отменить.
3. **Время в расписании — по лиге (UTC+7)**, как у сезонов: клубы в Новосибирске и Красноярске.

### Шаг 4. Срезы TDD 1–2: приветствие и согласие

Каждый срез — один тест (красный) → минимальный код (зелёный) → mypy.

- **Срез 1.** Тест «/start приветствует и просит согласие» и стенд `tests/bot.py`. Сначала диспетчер был пустым, красный: бот молчит. Обработчик `/start` → зелёный.
  - **Проблема по пути:** один `Router` aiogram нельзя подключить к двум диспетчерам, а тесты создают диспетчер на каждый чат. Решение: обработчики регистрируются на новом роутере внутри `create_dispatcher`.
- **Срез 2.** «После согласия бот просит телефон» (кнопка «Поделиться контактом») → красный → обработчик кнопки. Сообщение с кнопками после нажатия теряет кнопки, чтобы их не нажали дважды.

### Шаг 5. Срезы 3–7: привязка по телефону

- **Срез 3** — первый сквозной до базы: «свой контакт с телефоном, который завёл клуб, находит его карточку». Игрока заводит админ через API. Имя в Telegram («Ваня») отличается от клубного, и в ответе должно быть клубное — так видно, что найдена именно карточка клуба. Появились `conversation.py` (шаги с базой) и запуск шага в отдельном потоке.
- **Срез 4.** «Новый телефон заводит игрока с именем из Telegram». Свидетель — админ-API: админ вводит этот телефон и получает `added_to_club` с именем из Telegram, то есть игрок уже есть в лиге. **Проблема с инструментом:** замена имени в тестах через .NET в PowerShell искала файл в другой папке и ничего не изменила. Сделал замену через `sed` и проверил, что старых имён не осталось.

## Если что-то пошло не так

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Бот не отвечает, в `docker compose ps` сервиса `bot` нет или он `Exited (0)` | Нет токена: в логе «Бот не запущен: нет токена» | Создать `.env` в корне с `TELEGRAM_BOT_TOKEN=<токен от @BotFather>`, затем `docker compose up -d bot` |
| `bot` в состоянии `Restarting`, в логе `Unauthorized` | Неверный или отозванный токен | Взять токен в @BotFather (`/token`), исправить `.env`, `docker compose up -d bot` |
| В логе бота `TelegramConflictError: terminated by other getUpdates request` | Этот же токен запущен ещё где-то (второй компьютер, второй контейнер) | Остановить второй экземпляр: одному токену — один процесс polling |
| В логе бота `Cannot connect to host api.telegram.org` | Нет доступа к Telegram из сети или из Docker | Проверить интернет и VPN или прокси. Бот поднимется сам (`restart: on-failure`) |
| Бот стартует, но на сообщения падает с ошибкой про `telegram_users` | Миграция 0009 не применилась | `docker compose restart backend`, в логе должно быть `Running upgrade 0008 -> 0009`; затем `docker compose restart bot` |
| После правки кода бот ведёт себя по-старому | Бот не перезагружается сам | `docker compose restart bot` (после смены зависимостей — `docker compose up -d --build`) |
| «Это чужой контакт» | Контакт прислан через «Вложение → Контакт», а не кнопкой | Нажать кнопку «Поделиться контактом» внизу. Если её нет — `/start` |
| «Пока бот работает только с российскими номерами» | Номер Telegram-аккаунта не `+7` | Так задумано. Игрока заводит администратор клуба |
| Бот назвал не то имя, которое в Telegram | Телефон уже был в лиге, имя берётся из карточки клуба | Так задумано (ADR-0005) |
| В расписании нет турнира, который есть в админке | Турнир начат, отменён, у другого клуба, начался больше 12 часов назад или он не среди 10 ближайших | Проверить статус и клуб турнира. Сменить клуб — `/club` |
| Игрок выбрал клуб в боте, а админ его не видит | Страница «Игроки» открыта до этого (живого обновления от бота нет) | Обновить страницу |
| Тесты backend падают при подъёме базы с ошибкой про ревизию `0009` | Тестовая база на версии, которой нет в коде (например, после переключения веток) | `docker compose exec db psql -U poker -d poker_test -c "DROP TABLE IF EXISTS telegram_users; UPDATE alembic_version SET version_num='0008';"` и снова `pytest` |
| `ModuleNotFoundError: aiogram` при тестах на хосте | В `.venv` нет новой зависимости | `backend/.venv/Scripts/pip install -r backend/requirements-dev.txt` |
