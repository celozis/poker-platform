## Краткий итог

Администратор клуба входит в админ-панель по номеру телефона и одноразовому коду, без пароля. SMS в прототипе не отправляется: код пишется в лог backend. Панель оформлена в цветах клуба и с его логотипом, рядом всегда виден знак Сибирской лиги покера. В системе два тестовых клуба, «Обь» и «Енисей», у каждого свой администратор.

Заложена мультитенантность. Все данные клуба привязаны к клубу колонкой `club_id`. Все адреса API с данными клуба проходят через одну общую проверку. Администратор чужого клуба получает отказ 403.

Критерии приёмки из тикета:

| Критерий | Статус | Как проверено |
|---|---|---|
| Сид-скрипт создаёт два клуба с названием, логотипом, цветами и по одному администратору | ✅ | 2 backend-теста (`test_seed.py`). Вживую: `docker compose exec backend python -m app.seed` |
| Администратор вводит телефон, получает код (виден в логе), вводит код и попадает в панель | ✅ | Backend-тест берёт код прямо из лога. Frontend-тест проходит весь вход. Вживую: curl и headless Chrome для обоих клубов |
| Неверный или просроченный код не пускает в панель | ✅ | Backend-тесты: неверный код, просроченный код (время подменяется в тесте), 5 неверных попыток. Frontend-тест: сообщение об ошибке |
| Панель в цветах и с логотипом клуба, брендинг лиги тоже виден | ✅ | Frontend-тест проверяет цвет шапки, логотип и знак лиги. Скриншоты обоих клубов, в том числе на ширине телефона |
| Запрос к API данных чужого клуба возвращает отказ (покрыто тестом) | ✅ | `tests/test_club_access.py`: свой клуб → 200, чужой → 403, без входа → 401. Вживую через curl |
| Администратор может выйти из панели | ✅ | Backend-тест: после выхода даже скопированная старая cookie не работает. Frontend-тест: кнопка «Выйти» возвращает на экран входа |
| Записан ADR о подходе к мультитенантности | ✅ | `docs/adr/ADR-0003-multi-tenancy.md` |

Итог по тестам: **13 backend-тестов** (было 1) и **10 frontend-тестов** (было 4). Проверка типов (mypy strict и tsc) проходит, сборка frontend проходит. CI на GitHub зелёный.

## Как этим пользоваться

```bash
docker compose up --build -V                       # поднять всё (про -V см. шаг 9)
docker compose exec backend python -m app.seed     # создать тестовые клубы (один раз)
```

1. Откройте http://localhost:5173.
2. Введите телефон тестового администратора:

   | Клуб | Администратор | Телефон |
   |---|---|---|
   | Покер-клуб «Обь» (синий с золотым) | Анна Соколова | +7 999 000-00-01 |
   | Покер-клуб «Енисей» (бордовый с песочным) | Дмитрий Орлов | +7 999 000-00-02 |

   Номер можно вводить в привычном виде: `8 999 000-00-01`, `+7 (999) 000-00-01` и так далее.
3. Нажмите «Получить код» и найдите код в логе backend:
   ```bash
   docker compose logs backend | grep "Код входа"
   # INFO:     app.auth - Код входа для +79990000001: 929217
   ```
4. Введите код и нажмите «Войти». Откроется панель клуба.
5. «Выйти» в правом верхнем углу.

### Таблицы в базе

| Таблица | Что хранит | Важное |
|---|---|---|
| `clubs` | клуб: название, путь к логотипу, основной цвет и цвет акцента | общая таблица лиги, без `club_id` |
| `admins` | администратор: телефон (уникальный), имя, `club_id` | админ принадлежит ровно одному клубу |
| `login_codes` | ожидающий код входа: **хеш** кода, время отправки, срок действия, счётчик неверных попыток | по одной строке на телефон. Новый код заменяет старый |
| `admin_sessions` | сессия после входа: **хеш** токена, `admin_id`, срок действия | удаляется при выходе и вместе с админом |

Сами коды и токены в базе не хранятся, только их хеши SHA-256. Утечка дампа базы не даёт готовых токенов для входа.

### Адреса API

| Метод и адрес | Что делает | Ответы |
|---|---|---|
| `POST /api/auth/request-code` `{"phone": "..."}` | создаёт код и пишет его в лог | всегда **204**, даже для неизвестного номера (так нельзя выяснить, чей номер принадлежит админу) |
| `POST /api/auth/verify-code` `{"phone": "...", "code": "..."}` | проверяет код и ставит cookie `admin_session` | **204** при успехе, **401** «Неверный или просроченный код» |
| `GET /api/auth/me` | кто вошёл и его клуб | **200** `{admin, club}` или **401** «Требуется вход» |
| `POST /api/auth/logout` | удаляет сессию на сервере и cookie | **204** |
| `GET /api/clubs/{club_id}` | данные клуба (первый клубный адрес) | **200** — свой клуб, **403** «Нет доступа к этому клубу», **401** без входа |

### Правила входа

- Код: 6 цифр, действует **5 минут**.
- После **5 неверных попыток** код сгорает, и даже правильный код уже не пускает. Нужно запросить новый.
- Новый код на тот же номер отправляется **не чаще раза в минуту**. Повторный запрос раньше минуты молча ничего не делает: работает прежний код. Иначе каждый новый запрос обнулял бы счётчик попыток, и код можно было бы подобрать перебором.
- Сессия действует **7 дней**. Её хранит cookie `admin_session` с флагами `HttpOnly` (JavaScript её не видит), `SameSite=Strict` (не уходит с чужих сайтов) и `Path=/api`.

### Как части связаны между собой

```
Браузер (localhost:5173)
  │  App.tsx при загрузке спрашивает GET /api/auth/me
  │   ├─ 401 → LoginPage (телефон → код)
  │   └─ 200 → AdminPanel (цвета и логотип из club)
  ▼  все /api/* проксируются Vite на backend, cookie admin_session едет вместе с запросом
FastAPI (localhost:8000)
  ├─ app/auth.py   → current_admin: cookie → хеш → admin_sessions → admin
  └─ app/clubs.py  → AdminClub: current_admin + сравнение admin.club_id с {club_id} из адреса
  ▼
PostgreSQL (clubs, admins, login_codes, admin_sessions)
```

### Как добавить новый клубный адрес (для следующих тикетов)

По ADR-0003 любой адрес с данными клуба должен:

1. лежать под префиксом `/api/clubs/{club_id}/...` в `app/clubs.py` (или в роутере с тем же префиксом);
2. получать клуб только через параметр `club: AdminClub`;
3. фильтровать данные по `club.id`, а не по числу из адреса или тела запроса;
4. иметь тест, что админ чужого клуба получает 403, по образцу `tests/test_club_access.py`.

Если хоть один пункт пропустить, данные одного клуба могут стать видны другому. База сама этого не запрещает (см. «Известные ограничения»).

### Шаг 2. Backend: вход по коду, по TDD

Работал циклами «красный тест → минимальный код → зелёный тест». Каждый цикл добавлял один срез поведения.

1. **Цикл 1: сквозной вход.** Тест: админ запрашивает код, код берётся из лога, админ вводит его, `/me` возвращает админа и клуб.
   - Для этого теста понадобились модели (`models.py`), миграция `0002` и тестовые фабрики (`factories.py`).
   - В `conftest.py` добавил очистку всех таблиц после каждого теста (`TRUNCATE ... RESTART IDENTITY CASCADE`), чтобы тесты не влияли друг на друга.
   - Тест упал с **404**: эндпоинта ещё нет, это правильная причина. Миграция при этом применилась.
   - Написал `auth.py` (запрос кода, проверка, сессия, `/me`) и `schemas.py`. Тест позеленел.
   - В `main.py` настроил логгер `app`. **Без этого код в лог бы не попал.** Uvicorn настраивает только свои логгеры, а сообщения уровня INFO из приложения по умолчанию никуда не выводятся.
2. **Цикл 2: неверный код → 401.** Тест **сразу был зелёным**: сравнение кода уже было частью цикла 1. Оставил тест, потому что он фиксирует критерий приёмки.
3. **Цикл 3: просроченный код → 401.** Чтобы проверить срок действия без ожидания 5 минут, текущее время берётся через зависимость `get_now`. В тестах её заменяют управляемыми часами `FakeClock` (фикстура `clock`). Тест упал, потому что просроченный код принимался. Добавил проверку срока, тест позеленел.
4. **Цикл 4: 5 неверных попыток сжигают код.** Тест упал, потому что правильный код после 5 ошибок всё ещё пускал. Добавил счётчик `failed_attempts`, тест позеленел.
5. **Цикл 5: выход.** Тест: после выхода `/me` отвечает 401, и даже старая cookie, подставленная вручную, не работает. Упал с 404, добавил `POST /api/auth/logout`.
6. **Цикл 6: изоляция клубов**, три теста: свой клуб → 200, чужой → 403, без входа → 401.
   - Хелперы входа вынес в `tests/login.py`, чтобы ими пользовались разные файлы тестов.
   - Все три теста упали с 404. Написал `clubs.py` с зависимостью `AdminClub`, все позеленели.
7. **Цикл 7: сид-скрипт**, два теста.
   - Первый засевает базу, входит под каждым засеянным админом через API и проверяет, что клубы разные и у каждого есть название, логотип и цвета в формате `#RRGGBB`.
   - Второй проверяет, что повторный запуск ничего не ломает.
   - Упали с ошибкой импорта (модуля ещё нет). Написал `seed.py`, позеленели.
8. **Нормализация телефона.** Функцию `normalize_phone` я написал ещё в цикле 1, **без теста**, в нарушение правила «сначала тест». Тест на ввод «8 (913) 000-00-01» добавил позже, и он сразу был зелёным.

### Шаг 3. ⚠️ Мелкие проблемы на backend

- **mypy: `Source file found twice under different module names`.** Причина: тесты стали импортировать друг друга (`from tests.factories import ...`). Добавил пустой `tests/__init__.py`, после этого и mypy, и pytest видят тесты как пакет `tests`.
- **PowerShell портил файлы.** Сначала я дописывал тесты командой `Add-Content`. В Windows PowerShell 5.1 она добавляет в начало файла невидимую метку BOM и переводы строк CRLF. Нашёл это проверкой байтов, очистил файлы через `sed` и дальше редактировал только инструментами редактора. **Если в файле появились странные символы в первой строке**, причина, скорее всего, та же.

### Шаг 9. ⚠️ Особенность: `-V` при пересборке frontend

У контейнера frontend папка `node_modules` лежит в отдельном анонимном томе docker (так настроено в `docker-compose.yml` ещё в тикете #2). После добавления новых npm-пакетов (Tailwind) обычный `docker compose up --build` **оставил бы старый том без новых пакетов**, и Vite упал бы с ошибкой «не найден модуль `@tailwindcss/vite`». Флаг `-V` (`--renew-anon-volumes`) пересоздаёт этот том. **После любого изменения `frontend/package.json` запускайте `docker compose up --build -V`.**

### Шаг 10. Код-ревью

Запустил `/code-review`: два независимых ревьюера проверяли изменения относительно `18d9697`. Один сверял код со стандартами проекта, другой — с тикетом #3.

**Ревью по спеку.** Все 7 критериев выполнены. Замечания:
- с шага ввода кода нельзя вернуться к вводу номера: после просроченного или сгоревшего кода помогает только перезагрузка страницы;

- лимит попыток, разные форматы телефона и одинаковый ответ для неизвестных номеров — это сверх тикета, но ревьюер счёл их оправданными;

**Ревью по стандартам.** Нарушений документированных правил (ADR-0002 про синхронные обработчики, ссылки на ADR в комментариях, формат ADR) не нашлось. Замечания:
- **перебор кода:** каждый новый запрос кода обнулял счётчик неверных попыток, то есть попыток было бесконечно много;
- **гонка:** параллельные неверные попытки могли проскочить мимо лимита в 5;
- необработанные ошибки сети во frontend: при входе и при выходе;

- тест импортировал `FakeClock` из `conftest.py` (так в pytest делать не принято);
- невнятное имя хелпера `wrong()`;

- cookie без флага `secure`, старые коды и сессии не удаляются из базы.

**Что исправил:**

1. **Перебор кода.** Сначала написал красный тест «новый код отправляется не чаще раза в минуту». Затем добавил в `login_codes` колонку `sent_at` и проверку интервала `RESEND_INTERVAL`.

2. **Гонка.** Строка кода при проверке и при запросе блокируется `SELECT ... FOR UPDATE`, поэтому параллельные запросы по одному телефону идут по очереди.
3. **Ошибки во frontend.** Сначала два красных теста: «можно вернуться и исправить номер» и «при недоступном сервере показывается ошибка». Второй тест заодно поймал необработанное исключение. Затем:
   - в `LoginPage` ошибки сети показываются как «Не удалось связаться с сервером. Попробуйте ещё раз.»;
   - старая ошибка сбрасывается при новой попытке;
   - добавлена кнопка «Изменить номер».
4. **Выход при недоступном сервере.** Панель остаётся открытой и показывает сообщение. Если бы она закрывалась, пользователь думал бы, что вышел, хотя сессия на сервере жива и вернулась бы при следующей загрузке.
5. **Команда сида.** Теперь это `docker compose exec backend python -m app.seed`, при запущенном `docker compose up`, где миграции уже применены.
6. **Мелочи:**
   - cookie берётся через `Cookie(alias=SESSION_COOKIE)`;
   - параметры cookie собраны в одну константу `SESSION_COOKIE_SCOPE`;

**Что сознательно не стал менять** (см. «Известные ограничения»): флаг `secure`, очистку старых строк, ограничение по IP, дублирование маленького хелпера `json()` в двух тестовых файлах и отдельный тип для телефона.

## Известные ограничения и открытые вопросы

1. **Изоляция клубов держится на коде, а не на базе.** Это сознательный выбор (ADR-0003). Адрес, который обойдёт `AdminClub`, откроет чужие данные. Защита: правила из раздела «Как добавить новый клубный адрес» и обязательный тест на 403. Когда клубных таблиц станет много или к базе начнут ходить бот и отчёты, стоит добавить RLS в PostgreSQL.
2. **Cookie без флага `secure`.** Локально сайт работает по HTTP, и с этим флагом браузер не отправлял бы cookie. **Перед развёртыванием на сервер с HTTPS флаг нужно включить** (параметр `SESSION_COOKIE_SCOPE` в `app/auth.py`).
3. **Нет ограничения частоты запросов по IP.** Есть только лимиты на один номер: 5 попыток на код и новый код раз в минуту. Спек #1 упоминает rate limiting, его стоит сделать общим механизмом позже.
4. **Старые коды и сессии не удаляются из базы.** Просроченные строки просто перестают работать. Нужна периодическая очистка, пока объёмы мизерные.
5. **SMS не отправляется**, код пишется в лог. Для настоящей работы нужен SMS-шлюз: код отправляется в одном месте, в `request_code` в `app/auth.py`, рядом с комментарием про прототип.
6. **Логотипы клубов нарисованы для примера.** Настоящие файлы надо положить в `frontend/public/logos/` и поправить `logo_url` в сиде или в базе. Настройки брендинга через интерфейс пока нет: в спеке это отдельная история №20.
7. **Если `/api/auth/me` отвечает ошибкой сервера (5xx),** frontend показывает экран входа, как будто пользователь не вошёл. Что сломалось, видно в строке статуса внизу страницы.
8. **Адрес `/api/clubs/{club_id}` пока нужен только тестам.** Панель берёт данные клуба из `/me`. Настоящие клубные адреса (турниры, игроки) появятся в следующих тикетах.
9. **Прежние хвосты из тикета #2** (устаревшие версии GitHub Actions, раздел «Deployment» в `CLAUDE.md`, отдельный образ backend для продакшена) остались как были.

## Если что-то сломалось: куда смотреть

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| Кода нет в логе после «Получить код» | Номера нет среди админов (API всё равно отвечает 204, чтобы не выдавать, чей это номер) | Проверить телефон по таблице выше. Запустить сид |
| Кода нет в логе, хотя номер правильный | С прошлого запроса прошло меньше минуты: новый код не отправляется | Использовать прежний код из лога или подождать минуту |
| Кода нет в логе, номер нестандартный | `normalize_phone` понимает только российские номера из 11 цифр, начинающиеся на 7 или 8 | Ввести как `+7 999 000-00-01` |
| «Неверный или просроченный код» при правильном коде | Прошло больше 5 минут, код сгорел после 5 ошибок, или уже выдан более новый код | Нажать «Изменить номер», запросить код заново (через минуту после прошлого) |
| Строк `Код входа` вообще нет в логе backend | Сломалась настройка логгера `app` в `app/main.py` | Проверить блок с `logging.getLogger("app")` в `main.py` |
| Сид падает с `relation "clubs" does not exist` | Миграции не применены (например, запуск через `docker compose run` на чистой базе) | Сначала `docker compose up`, потом `docker compose exec backend python -m app.seed`. Или вручную `alembic upgrade head` |
| Frontend в контейнере: `Cannot find module '@tailwindcss/vite'` или нет стилей | Старый том `node_modules` (шаг 9) | `docker compose up --build -V` |
| Логотип не отображается | Нет файла в `frontend/public/logos/` или неверный `logo_url` в базе | Сверить путь в `clubs.logo_url` с файлом |
| API отвечает 403 «Нет доступа к этому клубу» | Запрошен не свой клуб. Это защита, а не ошибка | Проверить `club_id` в адресе и клуб вошедшего админа (`/api/auth/me`) |
| После входа всё равно 401 | Cookie не дошла: запрос не через `/api/...` или браузер блокирует cookie | Проверить в DevTools → Application → Cookies наличие `admin_session` с путём `/api` |
| Backend-тесты: одни тесты «видят» данные других | Сломана автоматическая очистка таблиц (фикстура `empty_tables` в `conftest.py`) | Проверить, что новые модели импортируются в `app/models.py` и попадают в `Base.metadata` |
| mypy: `Source file found twice under different module names` | Удалён `backend/tests/__init__.py` | Вернуть пустой файл |
| В первой строке файла странный символ, git показывает изменения во всех строках | Файл записан PowerShell (BOM и CRLF, шаг 3) | Пересохранить в UTF-8 без BOM с переводами строк LF |
| Backend падает при старте на миграции 0002 | Dev-база создана со старой версией 0002 (только если она у вас была до 26.09) | `docker compose exec backend sh -c "alembic downgrade 0001 && alembic upgrade head"`, затем сид |
