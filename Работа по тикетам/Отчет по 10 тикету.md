## Краткий итог

Бот лиги научился трём вещам, а админ-панель стала обновляться сама.

1. **Запись на турнир из бота.** Под расписанием (`/schedule`) у каждого турнира есть кнопка:
   ```
   Покер-клуб «Обь», ближайшие турниры:
   пт 2 октября, 19:30 — Пятничный турнир, бай-ин 2 000 ₽ — вы записаны
   сб 3 октября, 19:00 — Субботний турнир, бай-ин 2 000 ₽

   [Отменить запись: 2.10 Пятничный турнир]
   [Записаться: 3.10 Субботний турнир]
   ```
   После нажатия то же сообщение с расписанием обновляется на месте (пометка «вы записаны», другая кнопка), и приходит ответ: «Вы записаны на турнир «Субботний турнир», сб 3 октября, 19:00. Бай-ин оплачивается в клубе, когда придёте.»
2. **Админ-панель без перезагрузки.** Запись или отмена из бота появляется на странице «Регистрации» у администратора за доли секунды. На странице «Проведение» идущего турнира записавшийся из бота игрок сразу появляется в списке «Ждут посадки».
3. **`/rating`** показывает место и очки игрока в рейтинге клуба за текущий сезон и топ-10 клуба:
   ```
   Рейтинг клуба Покер-клуб «Обь», 2-е полугодие 2026
   Ваше место: 11, очков: 0, турниров: 1

   Топ-10:
   1. Гость 11 — 25
   2. Гость 10 — 14
   …
   ```
4. **Уведомления.** За 2 часа до старта (настраивается) бот напоминает записанным игрокам о турнире. После завершения турнира присылает место и очки: «Турнир «Вечерний турнир» завершён. Ваше место: 2 из 3, очков в рейтинг клуба: 2. Рейтинг клуба: /rating».

## Как этим пользоваться

### Запуск

Новых pip- и npm-пакетов нет, пересобирать образы не нужно.

```bash
docker compose up -d                          # если стек не запущен
docker compose restart backend bot            # после обновления кода: миграция 0010 и новый код бота
docker compose logs backend | grep 0010       # «Running upgrade 0009 -> 0010»
```

Backend применяет миграции только при старте контейнера. Автоперезагрузка по правке кода их не применяет, поэтому нужен `restart`.

### Настройка напоминания

За сколько минут до старта бот напоминает — переменная `BOT_REMINDER_MINUTES` в файле `.env` в корне проекта (там же, где токен). Без неё — 120 минут (2 часа).

```
TELEGRAM_BOT_TOKEN=...
BOT_REMINDER_MINUTES=180
```

После изменения: `docker compose up -d bot`.

### Сценарий для видео

1. Войдите в админку за «Обь» и создайте турнир на завтра. Откройте его страницу **«Регистрации»** и оставьте её на экране.
2. В Telegram (@pokerclub_test_bot) пройдите `/start` → согласие → контакт → «Покер-клуб «Обь»» (если ещё не проходили).
3. `/schedule` → нажмите **«Записаться: …»**. В боте: «Вы записаны…», в расписании пометка «вы записаны» и кнопка «Отменить запись». **В админке, не трогая страницу**, игрок появляется в списке «Зарегистрированные».
4. Нажмите **«Отменить запись»**. Игрок сразу исчезает из списка в админке.
5. Запишитесь снова. В админке отметьте его приход. В боте `/schedule` — кнопки отмены у этого турнира больше нет: оплатившего снимает только администратор.
6. **Поздняя регистрация:** начните в админке турнир с поздней регистрацией и откройте страницу «Проведение». В боте турнир виден как «идёт, поздняя регистрация до уровня N». Запишитесь — игрок сразу появляется в «Ждут посадки».
7. **Рейтинг:** доиграйте турнир с игроком из бота до конца. Через полминуты бот пришлёт «Турнир … завершён. Ваше место: …». Затем `/rating`.
8. **Напоминание:** создайте турнир, стартующий через 2 часа 5 минут, и запишитесь из бота. Минут через 5 придёт «Напоминаем: вы записаны на турнир…». Чтобы не ждать: `BOT_REMINDER_MINUTES=10` в `.env`, `docker compose up -d bot`, турнир через 15 минут.

### Изменения в базе (миграция 0010)

В таблице `registrations` два новых столбца, оба могут быть пустыми:

- `reminded_at` — когда бот напомнил игроку о турнире;
- `result_sent_at` — когда бот прислал результат.

Нужны, чтобы каждое уведомление ушло один раз. Откат: `alembic downgrade 0009` удаляет оба столбца.

### Как части связаны между собой

```
Игрок жмёт «Записаться» ──► бот (процесс bot)
                              │  в одной транзакции: INSERT registration + pg_notify('tournament_changed', id)
                              ▼
                          PostgreSQL ── после COMMIT доставляет уведомление ──►
                                                                              │
backend (процесс backend): поток-слушатель LISTEN ─► будит подписчиков турнира ┘
   ├── WebSocket табло  /api/board/<код>/ws       → читает табло заново, шлёт его целиком
   └── WebSocket админки /api/clubs/…/ws          → шлёт «changed»
                                                     │
                     страница «Регистрации» / «Проведение» → перечитывает данные REST-запросом

Бот, каждые 30 секунд: registrations без reminded_at / result_sent_at, которым пора →
   пометить отправленными → COMMIT → отправить в Telegram
```

### Правила (решения по покеру приняты мной, как вы поручили)

| Вопрос | Решение | Почему |
|---|---|---|
| Можно ли записаться из бота на уже идущий турнир? | Да, пока открыта поздняя регистрация; такой турнир виден в расписании с пометкой «идёт, поздняя регистрация до уровня N» | Так сказано в тикете («если не открыта поздняя регистрация»), и это те же правила, что в админке. Опоздавший приходит и садится через админа |
| Может ли игрок отменить запись из бота, если уже отметился в клубе? | Нет, и кнопки отмены у него нет. Бот объясняет, что снять запись и вернуть деньги может администратор | Отметившийся заплатил бай-ин. Возврат — сторно, его делает администратор, отдавая деньги в руки |
| Отмена записи после старта | Нельзя, кнопки нет | Как в админке: сняться можно только до старта |
| Кому напоминать | Всем записанным с привязанным Telegram (в том числе записанным администратором), кто записался раньше окна напоминания и ещё не отметился | Записавшемуся за 30 минут до старта напоминание бессмысленно; отметившийся уже в клубе |
| За сколько напоминать | 2 часа по умолчанию, `BOT_REMINDER_MINUTES` | Время доехать до клуба. Одно на лигу; нужно по клубам — станет полем клуба |
| Турнир перенесли после напоминания | Напоминание придёт снова, с новым временем | Старое напоминание сообщило неверное время |
| Результаты каких турниров слать | Только завершённых за последние сутки | Иначе при первом запуске бота или при поздней привязке Telegram игроку пришли бы старые результаты |
| Место исправили после отправки результата | Повторно не шлём | Редкий случай; исправленное видно в `/rating` |
| Топ-10 при равенстве очков на 10-м месте | Показываются все, делящие 10-е место | Иначе один из игроков с теми же очками пропал бы произвольно |

## Ход работы по шагам

### Шаг 1. Изучение задачи и окружения

Прочитал тикет #11, свои заметки о проекте, CONTEXT.md, ADR-0010 (бот), ADR-0007 (табло), код бота из #10, регистрации, рейтинг, `realtime.py` и страницы админки. По `/implement` сначала загрузил скилл `/tdd` через инструмент Skill. Проверил: стек в docker запущен, 18 тестов бота на хосте проходят.

Главная находка: ADR-0010 предупреждал, что бот и backend — разные процессы, а сигнал «турнир изменился» живёт в памяти backend. Изменение из бота само до админки не дойдёт. И у админ-панели вообще не было WebSocket — только у табло.

### Шаг 2. Решения с вами до начала работы

По `/tdd` согласовал с вами места тестирования (seams) и один архитектурный вопрос:

- **Seams — все три:** чат с ботом через настоящий диспетчер (эффект проверяется через админ-API); функция рассылки `send_notifications`; WebSocket админки + перечитывание на frontend.
- **Канал между процессами — PostgreSQL LISTEN/NOTIFY + WebSocket** (вы выбрали рекомендованный вариант вместо опроса раз в 5 секунд).

Правила покера (таблица выше) объявил сразу и принял сам.

### Шаг 3. Срезы 1–2: запись и отмена кнопками

- **Красный:** тест «нажал «Записаться: 3.10 Субботний турнир» → в админ-API игрок зарегистрирован». Кнопки не было.
- **Зелёный:** правила регистрации в `registrations.py` сделал общими (переименовал приватные функции в публичные), добавил кнопки и шаг `sign_up`.
- Для отмены и правки расписания на месте пришлось научить подставной Telegram в `tests/bot.py` хранить сообщения бота «как их видит игрок» — с правками (`EditMessageText`). Нажатие кнопки теперь ищет её в текущем виде сообщений.
- **Красный → зелёный:** «после записи расписание помечает турнир и предлагает отмену», «отмена снимает регистрацию». Шаги `sign_up`/`drop_out` возвращают `ScheduleChange` (ответы + свежее расписание), обработчик правит сообщение на месте.
- Мелкая ошибка по пути: mypy не принял тип клавиатуры при правке сообщения — сузил тип.

### Шаг 4. Срез 3: нельзя дважды и на начавшийся; поздняя регистрация

- Тесты «дважды нельзя» и «на начавшийся без поздней регистрации нельзя» прошли сразу: правила взяты из админки. Оставил их как фиксацию критериев приёмки.
- **Красный:** «идущий турнир с открытой поздней регистрацией есть в расписании, на него можно записаться». Сделал.
- Изменил старый тест из #10 (`…leaves_out_started_and_cancelled…`): «Идущий турнир» в нём теперь без поздней регистрации — иначе по новому правилу он законно остаётся в расписании.
- В одном тесте ошибся я сам (разбирал список турниров из API не того формата) — поправил тест.

### Шаг 5. Срез 4: `/rating`

- **Красный:** точный текст ответа для турнира на 12 игроков. Очки посчитал вручную по формуле лиги (25, 14, 10, 7, 5, 4, 3, 2, 2, 1, 0, 0), игрок из бота вылетает вторым — 11-е место, делит его с другим.
- **Зелёный:** шаг `rating` на готовой `club_standings` из рейтинга админки. Плюс тесты «игрока нет в рейтинге» и «в сезоне ещё нет завершённых турниров».

### Шаг 6. Срез 5: уведомления

- Тестовый стенд: `chat.check_notifications(remind_before)` вызывает `send_notifications` с ботом чата и подставными часами.

### Шаг 7. Срез 6: канал между процессами и WebSocket админки

## Если что-то пошло не так

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Бот падает с ошибкой про `reminded_at` / `result_sent_at` | Миграция 0010 не применилась | `docker compose restart backend`, в логе `Running upgrade 0009 -> 0010`; затем `docker compose restart bot` |
| Запись из бота не появляется в админке без перезагрузки | Страница открыта до перезапуска backend и не переподключилась; или прокси не пропускает WebSocket | Обновить страницу. В инструментах разработчика браузера (Network → WS) должно быть соединение `…/tournaments/<id>/ws`. В логе backend не должно быть «Нет связи с базой для уведомлений о турнирах» |
| В логе backend повторяется «Нет связи с базой для уведомлений о турнирах, повторим» | База недоступна или слушателю не хватает соединений | Проверить `docker compose ps db`. Слушатель переподключится сам, страницы после этого перечитают данные |
| Табло перестало обновляться после обновления кода | То же: сигнал теперь идёт через базу | Как выше; `docker compose restart backend` |

| Нет кнопки «Отменить запись» | Турнир уже идёт или игрок отметился в клубе | Так задумано: снимает администратор |
