## Краткий итог

Каждый бай-ин, re-entry и add-on теперь записывается как **денежная транзакция**. У неё есть способ оплаты (наличные или карта) и администратор, который её провёл. В админ-панели появилось:

- **Окно «Оплата»**. Оно открывается при каждом платном действии: отметка прихода, посадка опоздавшего, re-entry, add-on. В окне видно, за что платят и кто («Re-entry: Иван Петров»), и сумма («1 500 ₽»). Администратор выбирает кнопку **«Наличные»** или **«Карта»**; кнопка «Отмена» ничего не проводит. В бесплатном турнире окна нет.
- **Страница «Касса»** у каждого турнира. На неё ведёт кнопка **«Касса»** в списке турниров и на странице «Проведение». На странице:
  - **сводка**: по операциям (бай-ин, re-entry, add-on: сколько и на какую сумму), по способам оплаты, «Всего в кассе»;
  - **история операций**, последние сверху: номер, время, операция, игрок, способ оплаты, администратор, сумма;
  - у каждой действующей операции две кнопки: **«Сторнировать»** и **«Сменить на карту»** (или **«Сменить на наличные»**);
  - кнопка **«Выгрузить в CSV»**: файл открывается в Excel двойным щелчком.
- **Поле «Стоимость add-on, ₽»** в форме турнира.
- **Возврат денег.** Отмена прихода и снятие с регистрации пришедшего игрока сами сторнируют его бай-ин. На экране появляется подсказка «…бай-ин сторнирован: верните игроку 1 500 ₽». Отмена турнира сторнирует бай-ины всех, кто пришёл.

Критерии приёмки из тикета:

## Как этим пользоваться

```bash
docker compose up --build                          # поднять всё; миграция 0008 применится сама
docker compose exec backend python -m app.seed     # тестовые клубы и админы (если ещё не создавали)
```

Если стек уже запущен, достаточно `docker compose restart backend`: в логе должно появиться `Running upgrade 0007 -> 0008`. Новых npm- и pip-пакетов нет.

Сценарий для видео:

1. Войдите за «Обь» (`+7 999 000-00-01`), код: `docker compose logs backend | grep "Код входа"`.
2. **Создать турнир**: бай-ин 1500, add-on на уровне 1, фишек за add-on 30000, **стоимость add-on 1000**, re-entry до уровня 2, поздняя регистрация до уровня 2. Начало — через час-два, чтобы отметка прихода была открыта.
3. «Регистрации» → запишите 4 игроков → у каждого **«Отметить приход»**. Появится окно «Оплата · Бай-ин: … · 1 500 ₽». Двоим нажмите «Наличные», двоим «Карта».
4. У одного игрока нажмите **«Отменить приход»**. Появится «Приход игрока … отменён, бай-ин сторнирован: верните игроку 1 500 ₽». Отметьте его снова.
5. «Назад к списку» → **«Касса»**: 4 бай-ина, одна пара «бай-ин / сторно» в истории.
6. «Проведение» → «Начать турнир» → выбейте игрока → **«Re-entry»** → «Карта». У двоих **«Add-on»** → «Наличные».
7. Кнопка **«Касса»** вверху страницы «Проведение». Покажите сводку: бай-ин, re-entry, add-on, наличные/карта, «Всего в кассе».
8. У add-on нажмите **«Сторнировать»** → подтвердить. Строка зачёркнута, «Сторнирована операцией № N», сверху новая строка «−1 000 ₽ · Сторно операции № …». Кнопок у них больше нет.
9. У бай-ина, оплаченного наличными, нажмите **«Сменить на карту»** → подтвердить. Появятся сторно и новая оплата картой «Взамен операции № …». Сводка по способам оплаты поменяется, «Всего в кассе» — нет.
10. **«Выгрузить в CSV»** → откройте файл в Excel: история с примечаниями и итог внизу.

В рабочей базе после моей проверки остались турниры «Проверка кассы» (его операции удалены при повторном применении миграции, см. шаг 16) и «Касса: проверка» с десятью операциями и игроками «Касса 1…4» клуба «Обь». Их можно показать на видео или удалить пересозданием базы (`docker compose down -v`, стирает все данные).

### Адреса API

| Метод и адрес | Что делает |
|---|---|
| `POST …/registrations/{player}/check-in` с `{"payment_method": "cash"}` | Отметка прихода с оплатой бай-ина. Без способа оплаты → 422 «Укажите способ оплаты: наличные или карта». Повторная отметка денег не берёт. В бесплатном турнире тело не нужно |
| `DELETE …/registrations/{player}/check-in` | Отмена прихода, бай-ин сторнируется. Ответ: регистрация и `refunded` — сколько вернуть игроку |
| `DELETE …/registrations/{player}` | Снятие с регистрации (до старта). Теперь отвечает `200 {"refunded": N}` вместо `204` |
| `POST …/players/{player}/reentry`, `…/addon`, `…/seat` с `{"payment_method": …}` | Re-entry (цена бай-ина), add-on (цена add-on), посадка опоздавшего (бай-ин) |
| `POST …/cancel` | Отмена турнира; бай-ины пришедших сторнируются |
| `GET /api/clubs/{club}/tournaments/{id}/cashier` | `{by_kind, by_method, total, transactions}`. У транзакции: `id, created_at, kind, amount, payment_method, player, admin, reverses_id, replaces_id, reversed_by_id` |
| `GET …/cashier.csv` | Файл `kassa-{id}.csv` |
| `POST …/cashier/transactions/{id}/reverse` | Сторно. Отказы: 409 «Операция уже сторнирована», 409 «Сторно не сторнируют», 404 «Операция не найдена». Ответ — вся касса |
| `POST …/cashier/transactions/{id}/payment-method` с `{"payment_method": "card"}` | Смена способа: сторно и та же оплата другим способом. Тот же способ → 409 «Операция и так оплачена наличными». Ответ — вся касса |

Все адреса только для администратора своего клуба (чужой клуб → 403, без входа → 401).

### Правила

- **Бай-ин** платят при отметке прихода. Опоздавший платит при посадке через позднюю регистрацию. Запись на турнир (и из бота в тикете #11) бесплатна: это бронь.
- **Re-entry** стоит как бай-ин. **Add-on** стоит столько, сколько указано в турнире.
- **Сумма** берётся из правил турнира в момент операции и дальше не меняется. Если после отметки прихода поменять бай-ин турнира, уже принятые деньги остаются прежними, и возврат идёт на ту сумму, которую заплатили.
- **Бесплатный** турнир (бай-ин 0) и бесплатный add-on транзакций не создают, способ оплаты не спрашивается.
- **Возврат** (сторно бай-ина) делается сам: при отмене прихода, при снятии пришедшего игрока с регистрации до старта и при отмене турнира.
- **Сторно** — запись с противоположной суммой того же типа и способа. Исходная запись остаётся. Одну операцию сторнируют один раз, сторно не сторнируют. Сторно меняет только деньги, не игру: ошибочное выбывание отменяют на странице «Проведение».
- **Сводка**: суммы по типам, по способам и общая — с учётом сторно. «Кол-во» — операции, которые действуют (не сторно и не сторнированы). Смена способа оплаты не меняет ни количество, ни общую сумму.
- **CSV**: разделитель «;» и кодировка UTF-8 с BOM, чтобы русский Excel открыл файл без настройки. Время по UTC+7 (как у сезонов). Телефонов игроков в файле нет. Текст, который начинается с `=`, `+`, `-` или `@`, записывается с апострофом, чтобы Excel не принял его за формулу.

### Как части связаны между собой

```
отметка прихода ─┐
посадка опоздав. ├─ transactions.take_payment(цена по правилам, способ, админ) ─┐
re-entry, add-on ┘                                                                ├─ в одной транзакции БД
                                                          изменение игры/регистрации ┘

отмена прихода / снятие / отмена турнира ── transactions.give_buy_ins_back ── reverse (сторно)
                                                         └─ refunded ─→ подсказка «верните игроку N ₽»

касса ── GET cashier ── _cashier(все транзакции турнира) ── by_kind, by_method, total, история
      ├─ POST reverse ─────────── transactions.reverse
      ├─ POST payment-method ──── transactions.pay_again (сторно + оплата другим способом, replaces_id)
      └─ GET cashier.csv ──────── _csv(та же касса)
```

### Шаг 1. Изучение задачи и окружения

Прочитал тикет #9, родительский спек #1 (история №16 «управлять кассой: записывать бай-ины, re-entry, add-on, выплаты», раздел «Cashier: все транзакции атомарны, iiko sync append-only», «Online платежи: MVP = наличные на столе»). Прочитал тикеты, которые будут опираться на кассу: #13 (отчёты владельца: выручка по типам операций и способам оплаты за период), #12 (кабинет игрока: сумма бай-инов, re-entry и add-on), #11 (бот: запись на турнир — без оплаты). Прочитал глоссарий, ADR-0006 и ADR-0008, модули `game.py`, `registrations.py`, `tournaments.py`, `results.py`, `rating.py`, тесты и страницы фронтенда.

Выяснилось два пробела в модели:
1. **Оплаты при регистрации нет** — есть только запись и отметка прихода. Из тикета («Регистрация с оплатой») неясно, в какой момент игрок платит.
2. **Цены add-on нет** — в турнире есть только число фишек за add-on.

Docker был запущен. Базовый прогон до изменений: 181 backend-тест, 70 frontend-тестов, mypy и tsc без ошибок.

### Шаг 2. Решения до начала работы

С вами:

- **Бай-ин платят при отметке прихода.** Опоздавший платит при посадке. Отмена прихода и снятие оплатившего игрока с турнира сторнируют бай-ин сами. Другие варианты были: отдельная кнопка «Оплатить» (лишнее действие, и можно посадить неоплатившего) и оплата при регистрации (не подходит для записи из бота).
- **Исправление ошибок: сторно и смена способа оплаты.** Одного сторно мало: если у re-entry перепутали наличные и карту, провести правильную оплату было бы нечем.
- **Точки тестирования (TDD):** (1) API: приход, re-entry и add-on создают транзакции с суммой, способом и администратором, отмена прихода и снятие сторнируют; (2) API кассы: сводка, сторно, смена способа, CSV, изоляция клубов; (3) интерфейс кассы и выбора способа оплаты на подставном сервере.

Мои решения по покерным правилам (вы поручили их мне):

1. **Re-entry стоит как бай-ин.** Re-entry — это повторный вход в турнир, в клубах он почти всегда стоит столько же, сколько вход.
2. **У add-on своя цена** (поле «Стоимость add-on, ₽»). Add-on даёт другой стек, чем вход, и клубы обычно продают его по другой цене. Поле обязательно, если add-on предлагается (можно 0 — бесплатный add-on). Для уже созданных турниров миграция ставит цену add-on равной бай-ину: это самое частое значение.

## Что сознательно не сделано

- **Ручной ввод операции.** Каждая сумма происходит из действия в игре. Следствие: если бесплатный турнир сделать платным **после** того, как игроки отметили приход, с них уже не взять бай-ин через систему. Нужно отменить приход и отметить заново — тогда оплата пройдёт.
- **Транзакции для старых данных.** Бай-ины, re-entry и add-on до миграции 0008 в кассе не видны: неизвестны способ оплаты и администратор. После отмены такого старого прихода подсказки о возврате не будет: `refunded` = 0, это верно.
- **Выплаты, рейк, бар, комиссия дилерам** из спека #1. В спортивном покере выплат нет, а остальное — отдельные задачи (бар, отчёты владельца #13).
- **Скидки по статусу ЮДС и онлайн-оплата** — фаза 2 по спеку.
- **Синхронизация с iiko** — фаза 2. Журнал только добавляется, его можно будет выгружать по порядку номеров.
- **Касса клуба за период** — это отчёты владельца (#13). Сейчас касса по одному турниру.
- **Отмена самой игровой операции через кассу.** Сторно re-entry не убирает re-entry из игры (решение 5 на шаге 2).
