## Краткий итог

Администратор проводит турнир в админ-панели от старта до финального стола. У каждого турнира в списке появилась кнопка **«Проведение»**. На странице проведения администратор:

- видит, сколько игроков пришло, и нажимает **«Начать турнир»**. Система случайно рассаживает всех пришедших по наименьшему числу столов, разница между столами не больше одного игрока;
- следит за таймером блайндов: текущий уровень, блайнды и анте, обратный отсчёт, следующий уровень или перерыв. Таймер сам переходит на следующий уровень. Кнопки **«Пауза» / «Продолжить»**, **«Предыдущий уровень»**, **«Следующий уровень»**;
- отмечает выбывание игрока (кнопка **«Отметить выбывание»** с подтверждением) и видит его место. Ошибочное выбывание отменяется кнопкой **«Отменить выбывание»**;
- делает **re-entry** и **add-on**. Кнопки видны, только пока открыто окно из правил турнира;
- во время **поздней регистрации** сажает опоздавших записанных игроков и записывает новых, которые сразу садятся за стол;
- видит предложение пересадки («Столы неровные, пересадите: …») и выполняет его кнопкой **«Пересадить»**;
- видит, как система сама собирает **финальный стол**, когда игроки помещаются за один стол;
- когда остаётся один игрок, турнир завершается сам и показывает **«Итоги»** с местами. Завершённый турнир снова не запустить.

Состояния турнира: создан → идёт ⇄ пауза → завершён (или создан → отменён).

Критерии приёмки из тикета:

| Критерий | Статус | Как проверено |
|---|---|---|
| Старт рассаживает всех пришедших по столам, разница не больше одного | ✅ | Юнит-тесты `initial_seating` (2, 9, 10, 19, 25, 13 игроков при 9 и 6 местах). API-тест: 12 пришедших и 1 не пришедший дают столы 6 и 6, не пришедший ждёт. Тест интерфейса. Вживую: 12 игроков за 6-местными столами, 6 и 6 |
| Таймер идёт, показывает уровень и остаток, сам переходит на следующий уровень | ✅ | Юнит-тесты `BlindClock` (отсчёт, переход через уровни и перерыв, последний уровень). API-тест «двигает часы». Тест интерфейса: отсчёт 01:05 → 01:02 и новый запрос к серверу, когда время вышло |
| Пауза, продолжение, ручное переключение вперёд и назад | ✅ | Юнит- и API-тесты, отказы «Турнир уже на паузе», «Это первый/последний уровень структуры». Тест интерфейса. Вживую |
| Отметка выбывания фиксирует место | ✅ | API-тесты: места 4, 3, …, победитель 1. Место вычисляется из порядка выбывания, поэтому поздний игрок или re-entry после выбывания сдвигает его вниз, как и положено в итогах турнира (шаг 8, решение в шаге 22) |

| После выбывания, если столы разбалансированы, система предлагает конкретную пересадку | ✅ | Юнит-тесты `suggested_move`, в том числе «выполнение всех предложений выравнивает столы». API-тест: 18 игроков, 3 выбывания за столом 1, предложение «стол 2 → стол 1», выполнено, столы 8 и 7. Вживую |

| Логика рассадки, пересадки и окон покрыта юнит-тестами | ✅ | `test_seating.py` (20), `test_entry_windows.py` (16), `test_blind_clock.py` (8), без базы |

Итог по тестам: **135 backend-тестов** (было 59) и **44 frontend-теста** (было 28). Проверка типов (mypy strict и tsc) и сборка frontend проходят.

## Как этим пользоваться

```bash
docker compose up --build                          # поднять всё; миграция 0005 применится сама
docker compose exec backend python -m app.seed     # тестовые клубы и админы (если ещё не создавали)
```

Если стек уже запущен со старым кодом, достаточно `docker compose restart backend`. В логе должно появиться `Running upgrade 0004 -> 0005`. Новых npm-пакетов нет.

Сценарий для видео:

1. Войдите за «Обь» (`+7 999 000-00-01`), код смотрите командой `docker compose logs backend | grep "Код входа"`.
2. **«Турниры» → «Создать турнир»**. Время начала — через час или два: отметка прихода открыта за 12 часов до начала. Для короткого видео возьмите шаблон «Турбо» (уровни по 10 минут). В форме новое поле **«Мест за столом»** (по умолчанию 9). Чтобы показать несколько столов при небольшом числе игроков, поставьте, например, 4. Заполните правила: re-entry до уровня 2, add-on на уровне 2, поздняя регистрация до уровня 3.
3. **«Регистрации»** у турнира: запишите 8–10 игроков и отметьте приход у всех, кроме одного-двух.
4. **«Назад к списку» → «Проведение»**. Видно «Пришли: N из M». **«Начать турнир»**: появятся столы и таймер.
5. Покажите таймер: **«Пауза»** (надпись «на паузе»), **«Следующий уровень»** (уровень 2, появится подсказка «Сейчас можно взять add-on»), **«Продолжить»**.
6. У игрока нажмите **«Add-on»**: у него появится «add-on: 1», кнопка исчезнет.
7. **«Отметить выбывание»** у двух-трёх игроков одного стола. Внизу появятся «Выбывшие» с местами, сверху жёлтое предложение пересадки. Нажмите **«Пересадить»**.
8. У выбывшего нажмите **«Re-entry»**: он вернётся за стол с наименьшим числом игроков. Кнопка **«Отменить выбывание»** рядом исправляет ошибочную отметку и не считается re-entry.
9. Блок **«Поздняя регистрация»**: «Посадить» у пришедшего позже или поиск по имени → «Посадить».
10. Продолжайте отмечать выбывания. Когда оставшиеся поместятся за один стол, появится **«Финальный стол»** с новой рассадкой. Последнее выбывание завершает турнир: «Турнир завершён» и «Итоги».
11. В списке турниров идущий турнир показан в секции **«Идут сейчас»**, завершённый — в «Прошедших» с меткой «Завершён».

### Таблицы в базе (миграция 0005)

| `tournaments`, новые колонки | Тип | Что хранит |
|---|---|---|
| `seats_per_table` | integer, по умолчанию 9 | мест за столом |
| `status` | varchar(20), прежняя колонка | новые значения `running`, `paused`, `finished` |
| `started_at`, `finished_at` | timestamptz, NULL | когда запустили и когда завершился |
| `clock_item` | integer, NULL | какой элемент структуры (уровень или перерыв) играется; NULL до старта |
| `clock_ends_at` | timestamptz, NULL | когда он кончится, пока таймер идёт |
| `clock_remaining` | interval, NULL | сколько от него осталось, пока пауза |

| `registrations`, новые колонки | Тип | Что хранит |
|---|---|---|
| `table_number`, `seat_number` | integer, NULL | где сидит, пока в игре |
| `finish_order` | integer, NULL | 1 — первый выбывший и т. д.; победитель получает последний номер. Re-entry стирает |
| `reentries`, `addons` | integer, 0 | сколько сделано re-entry и add-on |
| `addon_this_entry` | boolean, false | add-on в текущем входе уже взят; re-entry сбрасывает |

Ограничения: место за столом уникально в турнире (`UNIQUE (tournament_id, table_number, seat_number)`, проверяется при фиксации транзакции, потому что финальный стол пересаживает всех разом); `finish_order` уникален в турнире.

Статус регистрации вычисляется: `out`, если есть `finish_order`; `in_game`, если есть стол; иначе `checked_in` или `registered`.

### Адреса API

Все адреса клубные и проходят через `AdminClub` (ADR-0003): **401** без входа, **403** «Нет доступа к этому клубу» для чужого клуба, **404** «Турнир не найден» для чужого турнира под своим клубом. Все действия отвечают полным состоянием игры `GameState`.

Префикс: `/api/clubs/{club_id}/tournaments/{tournament_id}`.

| Метод и адрес | Что делает | Отказы (409, если не сказано иное) |
|---|---|---|
| `GET /game` | состояние: `status`, `seats_per_table`, `clock {running, item, seconds_left}`, `windows {reentry, addon, late_registration}`, `in_game` (стол, место, re-entry, add-on, `addon_this_entry`), `out` (место), `waiting` (записаны, не сидят), `suggested_move` | — |
| `POST /start` | рассадка пришедших, таймер на первом уровне | «Для старта нужны хотя бы два пришедших игрока», «Турнир уже идёт», «Турнир уже завершён, его нельзя снова запустить», «Турнир отменён» |
| `POST /pause`, `/resume` | пауза и продолжение | «Турнир уже на паузе», «Турнир не на паузе» |
| `POST /next-level`, `/previous-level` | следующий / предыдущий уровень или перерыв, с полным временем | «Это последний уровень структуры», «Это первый уровень структуры» |
| `POST /players/{id}/knock-out` | выбывание; остался один — турнир завершён; помещаются за один стол — финальный стол | «Игрок X уже выбыл», «Игрок X не в игре»; **404** «Игрок не зарегистрирован на этот турнир» |
| `POST /players/{id}/undo-knock-out` | отмена ошибочного выбывания: игрок садится за стол с наименьшим числом игроков, re-entry не засчитывается, окно не нужно | «Игрок X ещё в игре», «Игрок X не в игре» |
| `POST /players/{id}/reentry` | выбывший возвращается за стол с наименьшим числом игроков | «Игрок X ещё в игре», «В этом турнире нет re-entry», «Re-entry закрыт: он был до уровня N» |
| `POST /players/{id}/addon` | add-on, один на вход | «В этом турнире нет add-on», «Add-on берут на уровне N и в перерыве после него», «Игрок X уже взял add-on» |
| `POST /players/{id}/seat` | посадить записанного опоздавшего (заодно отмечает приход) | «Игрок X уже в игре», «Поздняя регистрация закрыта: она шла до уровня N», «Турнир уже идёт, поздней регистрации в нём нет» |
| `POST /players/{id}/move` `{table, seat}` | пересадка: предложенная или любая на свободное место | «Стола N нет: пересадить можно за стол … или открыть стол M», «За столом места с 1 по 9», «Стол 1, место 3 занято» |

Для всех действий, кроме `GET /game` и `start`: «Турнир ещё не начался», «Турнир завершён», «Турнир отменён».

Изменения в прежних адресах:

- `GET /tournaments` возвращает `{live, upcoming, past}`. Секция `live` — идущие и на паузе.
- `POST /registrations`: до старта запись открыта всегда, даже если время начала прошло. После старта — только в окне поздней регистрации.
- `DELETE /registrations/{id}` — только до старта: «Турнир уже начался, снять с регистрации нельзя».
- Check-in и его отмена закрыты после старта: «Турнир уже начался: опоздавшего сажают через позднюю регистрацию».
- `GET /registrations` получил флаг `drop_out_open`.
- Изменить или отменить можно только не запущенный турнир, в том числе после его времени начала.

### Правила

| Правило | Где |
|---|---|
| Старт: столов `ceil(N / мест)`, игроки раздаются по столам по кругу после перемешивания, места за столом случайные | `initial_seating()` в `app/seating.py` |
| Новичку (поздняя посадка, re-entry): случайное свободное место за столом с наименьшим числом игроков (из равных — с меньшим номером); все полны — новый стол | `seat_for_newcomer()` |
| Пересадка: если столов больше, чем нужно, разбирается самый маленький (из равных — с большим номером), по одному игроку, к самому маленькому из оставшихся; иначе, если разница больше одного, — с самого большого на самый маленький. Пересаживается игрок с наименьшим номером места, на наименьшее свободное место. Одно и то же предложение при одинаковой рассадке | `suggested_move()` |
| Финальный стол: больше одного стола, а игроков не больше мест за столом — новая жеребьёвка за стол 1 | `final_table_seating()` |
| Таймер: элемент и время окончания (или остаток на паузе); закончившиеся элементы проматываются при каждом запросе; последний уровень идёт с остатком 0 | `BlindClock` в `app/blind_clock.py` |
| Окна: номер уровня для элемента = число уровней до него включительно (перерыв после уровня N → N, перерыв в самом начале → 0). Re-entry и поздняя регистрация — пока номер ≤ N; add-on — когда номер = N | `app/entry_windows.py` |
| Место = число игравших минус число выбывших раньше | `_places()` в `app/game.py` |
| Интерфейс: «Финальный стол» — один стол у турнира, в котором игравших больше, чем мест за столом | `Tables` в `GamePage.tsx` |

### Шаг 2. Решения, принятые с вами до начала работы

1. **Мест за столом** — новое поле турнира, по умолчанию 9, от 2 до 10.
2. **Перерыв после уровня N относится к уровню N**: окна «re-entry до N», «поздняя регистрация до N» и «add-on на N» на этом перерыве ещё открыты. Так add-on можно брать на перерыве, как обычно и делают в клубах.
3. **Турнир завершается сам**, когда остаётся один игрок; он получает первое место.
4. **Финальный стол собирается сразу** после выбывания, которое позволило его собрать, с новой жеребьёвкой мест.
5. **Швы для тестов**: юнит-тесты чистых модулей без базы (рассадка, таймер, окна), backend через HTTP API против настоящего PostgreSQL, frontend через всё приложение `<App/>` с фальшивым backend.

Решения, которые я принял сам и которые стоит знать:

- **«Турнир начался» теперь значит «администратор нажал старт»**, а не «наступило время начала». До этого тикета кнопки старта не было, и `CONTEXT.md` прямо говорил, что правило временное. Причина: клубы часто начинают с опозданием, и игрок, пришедший в 19:05 на турнир «в 19:00», который ещё не запустили, должен записаться. Последствия: до старта запись открыта, даже если время прошло; не запущенный вовремя турнир остаётся в «Предстоящих», и его можно отменить; после старта check-in закрывается, снять с регистрации нельзя.
- **Старт не проверяет время**, только что пришли хотя бы двое. Отметка прихода и так открыта только за 12 часов до начала, так что случайно запустить турнир за неделю не выйдет.
- **Для старта нужны хотя бы два пришедших игрока.**
- **Место вычисляется, а не записывается** (шаг 8).
- **Пересадку администратор подтверждает кнопкой.** Этот же адрес позволяет пересадить игрока на любое свободное место: без него предложение не выполнить.
- **Add-on — один на вход.** В правилах турнира указан только уровень, а без ограничения add-on можно было бы брать сколько угодно раз.
- **Re-entry — сколько угодно раз, пока открыто окно.** Правила ограничивают только уровень.

### Шаг 8. Модуль `app/game.py`: состояние и старт

`GET /game` и `POST /start`. Все действия блокируют строку турнира (`for_update`), так что параллельные изменения одной игры идут по очереди, и все отвечают полным `GameState`.

**Место вычисляется** в `_places()`: число игравших минус число выбывших раньше. Выбывание записывает `finish_order`, победитель получает следующий номер. Почему не записывать место в момент выбывания: при re-entry или поздней посадке после выбывания записанные места пришлось бы переписывать, иначе появились бы дубли и дыры. Пример: из 10 выбыл А (10-й), потом Б (9-й), потом А сделал re-entry. Теперь Б — первый выбывший, то есть 10-й. Если после этого придёт поздний игрок, Б станет 11-м. Подробности — в ADR-0006.

### Шаг 22. Решения по двум открытым вопросам и отмена выбывания

Я задал вам два вопроса: устраивает ли вычисляемое место и нужна ли кнопка «Отменить выбывание». Вы поручили решить, как, по-моему, хотел бы заказчик.

1. **Место остаётся вычисляемым из порядка выбывания.** Так итоги считают в покере: выше тот, кто продержался дольше, а поздние входы (re-entry, поздняя регистрация) сдвигают вниз тех, кто вылетел раньше. Если записывать место в момент выбывания, в итогах появились бы дубли и пропуски.
2. **Кнопка «Отменить выбывание» добавлена.** Администратор за столом неизбежно иногда ошибается, а исправлять ошибку через re-entry неправильно: re-entry — это новый бай-ин, и в кассе (тикет #9) он станет деньгами.
   - TDD: API-тесты (красные, потом зелёные). Отмена работает вне окна re-entry и в турнире без re-entry, счётчик re-entry не растёт, места остальных пересчитываются. Отменить можно только у выбывшего и только пока турнир идёт или на паузе. У завершённого турнира отказ «Турнир завершён»: исправление мест после завершения — тикет #8.
   - Адрес `POST /players/{id}/undo-knock-out` добавлен в тесты изоляции клубов (403, 404, 401).
   - Игрок садится за стол с наименьшим числом игроков, как при re-entry. На прежнее место не возвращается: оно могло быть занято после пересадки или финального стола.
   - Проверка «игрок выбыл» повторялась в re-entry и в отмене, вынесена в `_require_out()`.
   - Интерфейс: кнопка «Отменить выбывание» у каждого в списке «Выбывшие», пока турнир не завершён; в «Итогах» кнопок нет. Тест интерфейса.
   - `CONTEXT.md`: в термине Knock-out сказано, что ошибочное выбывание отменяется и это не re-entry.

## Известные ограничения и открытые вопросы

1. **Место вычисляется из порядка выбывания** (решение из шага 22). Если после выбывания игрока кто-то сделает re-entry или сядет по поздней регистрации, место выбывшего сдвинется. Тикет #8 (исправление места и рейтинг) потребует записывать итоговые места при завершении турнира (ADR-0006).
2. **Турнир завершается, когда остался один игрок**, даже если окно re-entry или поздней регистрации ещё открыто (ваше решение). Выбывший предпоследним лишается re-entry.
3. **Старт не проверяет время начала.** Удерживает только то, что отметка прихода открыта за 12 часов.
4. **Re-entry или поздняя посадка после заполненного финального стола** открывают стол 2 с одним игроком. Система предлагает пересадки, а следующее выбывание снова собирает финальный стол. Если администратор сам разнесёт игроков по двум столам через пересадку, финальный стол соберётся только при следующем выбывании.
5. **Метка «Финальный стол»** в интерфейсе ставится, когда остался один стол, а игравших больше, чем мест за столом. В маленьком турнире с поздними игроками единственный стол может получить эту метку, хотя его не собирали.
6. **Поздняя запись нового игрока — два запроса** (запись, потом посадка). В редком случае окно закроется между ними, и игрок останется в «Ждут посадки».
7. **Нет истории хода игры** (кто когда выбыл, кого куда пересаживали), только текущее состояние. Журнал действий администратора из спека #1 — отдельная задача.
8. **Отмена выбывания работает, только пока турнир идёт.** Если ошибочно отмечено последнее выбывание и турнир уже завершился, вернуть его нельзя. Места завершённого турнира исправляются в тикете #8.
9. **Табло, WebSocket, касса и рейтинг** — тикеты #7–#9. Табло сможет считать отсчёт так же, как админ-панель, по `seconds_left` (ADR-0006).
10. **Интерфейс не проверен в браузере** в этой сессии: только тестами и через API на живом стеке.
11. **Прежние хвосты** из тикетов #2–#5 (флаг `secure` у cookie, очистка старых кодов и сессий, ограничение частоты запросов, раздел «Deployment» в `CLAUDE.md`, согласие одного клуба) остались как были.

## Если что-то сломалось: куда смотреть

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| `column "seats_per_table"` (или `clock_item`, `table_number`, `addon_this_entry`) `does not exist` | Миграция `0005` не применилась | `docker compose restart backend`, в логе должно быть `Running upgrade 0004 -> 0005` |
| Backend-тесты падают на старте с `column "addon_this_entry" ... does not exist` | Тестовая база осталась на старой версии миграции (шаг 19) | `docker compose exec -T db psql -U poker -d poker_test -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"` |
| Dev-база когда-то получила черновую `0005` без `addon_this_entry` (запускали код до исправления) | Версия `0005` в базе старая | `docker compose exec backend alembic downgrade 0004` **старым кодом** или вручную `ALTER TABLE registrations ADD COLUMN addon_this_entry boolean NOT NULL DEFAULT false` |
| Нет кнопки «Проведение» | Турнир отменён, или фронтенд со старым кодом | Ctrl+F5; у отменённого кнопки нет по задумке |
| «Для старта нужны хотя бы два пришедших игрока» | Приход отмечен меньше чем у двух | «Регистрации» → «Отметить приход» (открыто за 12 ч до начала) |
| Нет кнопки «Отметить приход» после старта | После старта check-in закрыт | Опоздавшего сажают в блоке «Поздняя регистрация» |
| Нет блока «Поздняя регистрация» | Окно закрыто или в турнире его нет | Смотрите «Поздняя регистрация до уровня» в правилах турнира |
| Нет кнопки «Re-entry» / «Add-on» | Окно закрыто, или add-on в этом входе уже взят | Подсказки под таймером показывают, что открыто |
| Таймер застыл на 00:00 на последнем уровне | Так задумано: дальше уровней нет | — |
| Таймер застыл на 00:00 не на последнем уровне, есть «Не удалось загрузить турнир» | Запрос в конце уровня не дошёл | Обновить страницу; проверить `docker compose logs backend` |
| Таймер в интерфейсе не совпадает с ожидаемым | Часы сервера | `docker compose exec backend date -u`; сервер считает от своего времени |
| Предложение пересадки не исчезает | Столы ещё неровные, нужно несколько пересадок | Выполнить следующее предложение |
| «Стола N нет…» | Пересадка за стол, которого нет в игре | Выбрать стол из сообщения или следующий номер |
| Место выбывшего изменилось | После него был re-entry или поздняя посадка (открытый вопрос 1) | Так задумано |
| Двойной клик ничего не сделал второй раз | Защита от повторного действия | Так задумано |
| Выбывание отмечено не тому игроку | Ошибка за столом | «Отменить выбывание» в списке «Выбывшие», пока турнир не завершён |
| curl из Git Bash: 400 «There was an error parsing the body» | Кириллица в аргументах ушла не в UTF-8 | Python-скрипт или `--data-binary @file.json` |
