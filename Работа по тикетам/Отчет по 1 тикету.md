Написал `docker-compose.yml` с тремя сервисами (`db`, `backend`, `frontend`), оба Dockerfile и SQL-скрипт, который при первом запуске создаёт отдельную базу `poker_test`.

### Шаг 4. ⚠️ Проблема: образы с Docker Hub не скачиваются

**Симптом.** `docker compose up` долго ничего не выводил. `docker pull postgres:16-alpine` зависал на строке `Pulling fs layer`, прогресс оставался на нуле.

**Диагностика.** Сам сервер Docker Hub отвечал (`registry-1.docker.io` → 401, это нормально). Не скачивались сами файлы образов. Зеркало Google `mirror.gcr.io` работало быстро. Скорее всего, сеть ограничивает доступ к хранилищу файлов Docker Hub.

**Что сделал.** Только на этом компьютере скачал базовые образы через зеркало и переименовал их под стандартные имена:
```bash
docker pull mirror.gcr.io/library/python:3.12-slim && docker tag mirror.gcr.io/library/python:3.12-slim python:3.12-slim
docker pull mirror.gcr.io/library/node:22-alpine   && docker tag mirror.gcr.io/library/node:22-alpine node:22-alpine
```
Образ `postgres:16-alpine` в итоге докачался и с Docker Hub, примерно за 15 минут.

**Важно.** В файлах проекта остались обычные имена образов. На GitHub и на будущем сервере Docker Hub доступен, там обход не нужен.

**Если повторится** (новый компьютер, после очистки Docker): выполните команды выше, а для Postgres ту же пару с `postgres:16-alpine`. Другой вариант — прописать `mirror.gcr.io` как зеркало в настройках Docker Desktop (Settings → Docker Engine → `"registry-mirrors"`).

### Шаг 6. ⚠️ Проблема: порт 5432 занят

**Симптом.** Backend-тест не мог подключиться к базе и получал ошибку пароля **на русском языке**.

**Диагностика.** Контейнер Postgres отвечает по-английски, значит, отвечал кто-то другой. На компьютере установлена **служба Windows `postgresql-x64-18`** (локальный PostgreSQL 18). Она слушает порт 5432 и перехватывала подключения.

**Решение.** Снаружи контейнерная база теперь доступна на порту **5433** (`"5433:5432"` в `docker-compose.yml`). Внутри docker-сети сервисы по-прежнему ходят на 5432. Локальную службу я не трогал.

**Если тесты на хосте не подключаются к БД:** проверьте, что запущен `docker compose up -d db` и что вы подключаетесь к порту 5433.

### Шаг 10. Код-ревью

Запустил `/code-review`: два независимых ревьюера проверяли изменения относительно `a21d6b1`.

**Ревью по стандартам.** Кодстайла в проекте нет, поэтому проверка шла по `docs/agents/domain.md` и базовому списку «запахов кода». Найдено:
- ADR-0001 смешивает несколько решений, а `domain.md` требует одно решение на ADR;
- код, который зависит от ADR, не ссылается на него в комментариях;
- в `CONTEXT.md` не обновлён обзор архитектуры;
- строка подключения к БД повторяется в нескольких файлах;
- команда запуска backend записана дважды (в Dockerfile и в compose);
- статусы здоровья — «голые» строки без типов;
- в тестах повторяется код подмены `fetch`.

**Ревью по спеку.** Найдено:
- CI не проверен, потому что ничего не отправлено на GitHub;
- страница не читала поле `api` из ответа backend;
- база `poker_test` создаётся только при первом создании тома;
- тесты стирают любую базу, на которую указывает `TEST_DATABASE_URL`;
- Tailwind из спека #1 не подключён.

**Что исправил:**
1. Ответ `/api/health` строго типизирован: в backend модель `Health` с `Literal["ok", "unavailable"]`, во frontend такой же тип. Страница показывает «API работает» только если `api === "ok"`.
2. Команда запуска backend осталась только в Dockerfile. Compose добавляет `--reload` через переменную `UVICORN_EXTRA_ARGS`. Uvicorn запускается через `exec`, чтобы корректно получать сигнал остановки.
3. **Защита тестов:** `conftest.py` отказывается работать, если имя базы не заканчивается на `_test`. Проверил: при `TEST_DATABASE_URL=.../poker` тесты завершаются с сообщением `Refusing to reset non-test database 'poker'`.
4. Решение о синхронных сессиях вынесено в отдельный ADR-0002, а `db.py` ссылается на него в комментарии.
5. В тестах frontend появился общий хелпер `stubFetch`.
6. В `CONTEXT.md` появилась оговорка про `poker_test` на старом томе и упоминание ADR-0002 в обзоре архитектуры.

**Что сознательно не стал менять:**
- Строка подключения к БД повторяется в compose, CI и тестах. Это разные окружения, и общий источник сейчас усложнил бы больше, чем помог.
- ADR-0001 остался одним документом о стеке: тикет прямо просит «ADR о выборе стека».
- Tailwind не подключён (см. ниже).

После исправлений всё перепроверено: тесты, типы, защита тестов, пересборка compose и ответ `/api/health`.

## Известные ограничения и открытые вопросы

1. **CI не проверен.** Сделайте push и убедитесь, что оба задания GitHub Actions зелёные. После этого тикет #2 можно закрывать.
2. **Tailwind CSS не подключён**, хотя он указан в спеке #1. По ADR-0001 подключим его вместе с первым экраном с настоящей вёрсткой.
3. **Когда база упала, `/api/health` отвечает примерно 8 секунд**: столько ждётся попытка подключения. Можно ускорить таймаутом подключения (`connect_timeout`), если станет важно.
4. **Первая миграция `0001` пустая.** Она только заводит учёт миграций, а таблицы появятся в тикете #3.
5. **Переводы строк.** В git включён `core.autocrlf=true`, и git предупреждает `LF will be replaced by CRLF`. Сейчас это безопасно. Но если в проекте появятся shell-скрипты (`.sh`), которые запускаются внутри Linux-контейнеров, нужен файл `.gitattributes` с `*.sh text eol=lf`. Иначе скрипты сломаются из-за CRLF.
6. **Раздел «Deployment» в `CLAUDE.md`** всё ещё «To be filled in». CI сейчас только тестирует и ничего не разворачивает.
7. **Образ backend для продакшена** пока не сделан. Сейчас в образ ставятся и dev-зависимости (pytest, mypy). Для сервера понадобится отдельная сборка.

## Если что-то сломалось: куда смотреть

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| `docker compose up` висит, образы не качаются | Docker Hub недоступен из сети (шаг 4) | Скачать образы через `mirror.gcr.io` |
| `failed to connect to the docker API ... dockerDesktopLinuxEngine` | Docker Desktop не запущен | Запустить Docker Desktop и подождать ~1 минуту |
| Тесты на хосте: ошибка пароля на русском | Подключение ушло в локальный PostgreSQL на 5432 (шаг 6) | Использовать порт 5433, запустить `docker compose up -d db` |
| Тесты: `database "poker_test" does not exist` | Том `pgdata` создан раньше, чем появился init-скрипт | `docker compose exec db createdb -U poker poker_test` |
| Тесты: `Refusing to reset non-test database` | `TEST_DATABASE_URL` указывает не на тестовую базу | Исправить переменную; это защита, а не баг |
| На странице «API недоступен» | Backend не запущен или упал | `docker compose logs backend` |
| На странице «База данных недоступна» | Контейнер `db` остановлен или не здоров | `docker compose ps`, `docker compose logs db` |
| Ошибка `@rolldown/binding-wasm32-wasi` во frontend | Не до конца установлены `node_modules` | `cd frontend && npm ci` |
| Изменения кода не подхватываются в контейнере | Не работает слежение за файлами на Windows | Перезапустить сервис: `docker compose restart backend` / `frontend` |
| Backend падает при старте на миграции | Ошибка в файле миграции или база недоступна | `docker compose logs backend`, найти строки `alembic` |
