## Краткий итог

1. **Раздел «Команда» у владельца клуба.** Администратор этого раздела не видит.
   - **«Добавить сотрудника»**: имя и телефон. Новый администратор сразу входит в админку по этому телефону.
   - **«Команда клуба»**: сначала владельцы с пометкой «Владелец», затем администраторы по алфавиту с кнопкой **«Убрать»**. Перед удалением владелец подтверждает действие.
   - **Убранный сотрудник не удаляется, а получает отметку с датой.** Код входа ему больше не приходит, его открытые сессии закрываются в тот же момент. Его имя остаётся в кассе и журнале турниров.
   - **Повторное добавление телефона убранного администратора возвращает его** под прежним именем.
   - Телефон сотрудника другого клуба, действующего или убранного, даёт отказ: «Этот телефон уже у сотрудника другого клуба лиги. Один человек может быть в команде только одного клуба».
   - Владельца (себя или другого) убрать нельзя: «Владельцев клуба меняет лига».
   - **«Журнал клуба»** под списком: кто и когда добавил, вернул или убрал сотрудника. Действия команды лиги подписаны «лига».
2. **Команда лиги для разработчика**: `python -m app.league` в контейнере backend.
   - `clubs` — список клубов с номерами, цветами и владельцами.
   - `create-club` — завести клуб: название, два цвета, логотип лиги по умолчанию.
   - `rename-club` — переименовать клуб.
   - `appoint-owner` — назначить владельца (клуб, имя, телефон).
   - `dismiss-owner` — снять владельца по телефону.

   При отказе команда печатает «Не сделано: причина» и ничего не меняет. Владельцев она берёт и убирает теми же функциями, что и «Команда».
3. **Демо-данные.**
   - Клуб «Томь» и его владелицу заводят функции команды лиги.
   - Остальных администраторов владельцы добавляют через API «Команды».
   - Администратор «Оби» **Виталий Осипов** работал в турнирах и убран 10 дней назад. Войти он не может, но его имя есть в кассах и журналах.
4. **Документы.**
   - В CONTEXT.md добавлены термины «League Command» и уточнённые «Team», «Action Log», а также раздел «League command» с пошаговыми примерами.
   - Новый ADR-0015.
   - В чек-лист добавлены разделы 4.14 «Команда» (Км1–Км13) и 4.15 «Команда лиги» (Лг1–Лг8).

## Как этим пользоваться

### Запуск

```bash
docker compose up -d --build                      # миграция 0015 применится при старте backend
docker compose exec backend python -m app.demo    # свежие демо-данные (в т. ч. команда и журналы клубов)
```

Если backend уже был запущен до этого коммита, миграцию можно применить вручную: `docker compose exec backend alembic upgrade head`.

### Команда лиги

```bash
docker compose exec backend python -m app.league clubs
docker compose exec backend python -m app.league create-club "Покер-клуб «Иртыш»" --primary "#1E3A8A" --accent "#FBBF24"
docker compose exec backend python -m app.league appoint-owner 4 "Глеб Иртышов" "+7 999 000-00-14"
docker compose exec backend python -m app.league rename-club 4 "Покер-клуб «Иртыш-Арена»"
docker compose exec backend python -m app.league dismiss-owner "+7 999 000-00-14"
```

Номер клуба берётся из `clubs`. Телефон с пробелами нужно взять в кавычки. Подробное описание есть в CONTEXT.md, раздел «League command».

### Что смотреть в демо

- Войти владельцем «Оби» (+7 999 000-00-11) → «Команда». В списке Олег (владелец), Анна и Сергей. В «Журнале клуба» сверху «Сотрудник убран · Олег Владимиров · Виталий Осипов, +7 999 000-00-31», ниже «Сотрудник добавлен» для Виталия и Сергея.
- Владелица «Томи» (+7 999 000-00-13) → «Команда» → в журнале «Назначен владелец · лига».
- Касса или журнал любого завершённого турнира «Оби» → среди сотрудников есть Виталий Осипов.
- Код на телефон Виталия (+7 999 000-00-31) не приходит.

## Решения, принятые с вами до начала работы

- **Где тестировать (seams)**: все три точки, как в спецификации. Первая — HTTP API бэкенда (TestClient и настоящий PostgreSQL). Вторая — функция-вход команды лиги на тестовой базе с проверкой результата через API, как тест сида. Третья — экран «Команда» через App и fakeBackend.

### Решения, которые я принял сам

Об этих решениях я сказал вам перед началом работы, возражений не было. Все они записаны в ADR-0015.

1. **Возвращённый сотрудник приходит администратором и с прежним именем**, даже если раньше был владельцем. Владельцев назначает только лига. Имя не перезаписывается, как и у игроков: клуб знает человека под этим именем, а журнал показывает имя по ссылке.
2. **Если лига назначает владельцем действующего администратора этого клуба, он становится владельцем.** Отказ в этом случае был бы бессмысленным.
3. **«Снять владельца» закрывает доступ полностью.** Если человек должен остаться администратором, новый владелец вернёт его через «Команду».
4. **В списке «Команды» только действующие сотрудники.** Убранные видны в журнале клуба.
5. **Действия лиги видны в журнале клуба с подписью «лига».** Для этого добавлена колонка `by_league`. Без неё пустое поле администратора значило бы «игрок». Выводить «лигу» из вида действия неявно, а позже то же действие сможет делать экран владельца сети.
6. **Телефон убранного сотрудника другого клуба тоже занят.** Строка остаётся, а телефон в базе уникален. Перевода сотрудника между клубами нет (см. «Что сознательно не сделано»).
7. **Заведение клуба в журнал не пишется**: до этого момента у клуба нет журнала. Переименование пишется.
8. **Нейтральные по роду сообщения**: «Виктор Осипов теперь в команде», «… снова в команде», «… больше не в команде». Формы вроде «добавлен» и «убран» в интерфейсе не подходят к женским именам («Анна добавлен»). В журнале «Сотрудник добавлен» относится к слову «сотрудник», поэтому там это правильно.
9. **Сид возвращает своих сотрудников**, если владелец их убрал. Иначе тестовые входы из CONTEXT.md перестали бы работать после проверки «Убрать».

### Шаг 3. Бэкенд «Команды» (TDD, по одному тесту за цикл)

Каждый цикл начинался с красного теста.

1. Владелец видит владельцев и администраторов своего клуба, но не чужого → маршрут `GET /team` в новом `app/team.py`.
2. Добавленный администратор входит и видит клуб → `POST /team`, функция `take_on`.
3. Убранный сразу разлогинен и не получает код. Для этого добавлены миграция 0015 (`removed_at`), фильтр в `request-code` и `verify-code`, проверка в `current_admin` и функция `let_go`, которая удаляет сессии. Тест держит администратора во втором «браузере» (отдельный `TestClient`).
4. Имя убранного остаётся в кассе и журнале. **Тест сразу был зелёным**: строка не удаляется, значит, правило уже выполнено. Я оставил тест, потому что он закрепляет критерий приёмки.
5. Повторное добавление возвращает убранного (ответ 200, `outcome: returned`, тот же `id`, прежнее имя).
6. Телефон сотрудника другого клуба даёт отказ 409 (параметры: «работает там» и «убран там»).
   - Первая версия теста ставила отметку «убран» прямо в базе, то есть проверяла через побочный канал.
   - Это нарушает правило `/tdd`, поэтому подготовку я переписал через API: владелец другого клуба сам убирает своего сотрудника.
7. Тот, кто уже в команде (администратор или владелец), не добавляется второй раз (409 «… уже в команде клуба»).
8. Владельца, себя или другого, убрать нельзя (409 «Владельцев клуба меняет лига»).
9. Доступ проверен для GET, POST и DELETE: без входа 401, администратору 403, владельцу чужого клуба 403.
   - Текст 403 у `OwnerClub` был «Отчёты клуба видит только владелец», для «Команды» он неверен.
   - Сделал общий текст «Это видит только владелец клуба» и поправил его в `fakeBackend`.
10. Проверка имени и телефона (422 со списком причин). Текст про формат телефона вынесен в `auth.PHONE_FORMAT`, его берут и игроки, и команда.
11. Изменения команды пишутся в журнал клуба, последние сверху; турнирные записи туда не попадают. Добавлены `app/club_log.py` и три новых вида журнала. Подробности записи имеют вид «Имя, +7 913 000-00-05». Позже я добавил журнал клуба и в тест доступа.

После шага 11 mypy нашёл один `Any` в тестовом помощнике, я его исправил.

### Шаг 4. Команда лиги (TDD)

1. Новый клуб и назначенный владелец: владелец входит, видит свой клуб с цветами и логотипом `/logos/league.svg`.
   - Это файл `app/league.py`, `main(argv)` на `argparse`.
   - Владелец назначается через `take_on(..., role="owner")`.
   - Номер клуба тест берёт из вывода команды («… (№ 3)»).
2. Действия лиги видны в журнале клуба с `by_league: true`.
   - Добавлены колонка `by_league` в ту же миграцию 0015 и параметр `record(..., by_league=...)`.
   - **Проблема:** тестовая база уже стояла на первой версии миграции 0015, без колонки. При откате фикстура падала на `drop_column("by_league")`.
   - **Решение:** один раз добавил колонку в `poker_test` вручную (`ALTER TABLE action_log ADD COLUMN IF NOT EXISTS by_league ...`), после этого фикстура откатила и подняла миграции заново.
   - Рабочую базу это не затронуло: на ней 0015 применялась уже в окончательном виде.
3. Переименование клуба: новое название видно в `/me`, в журнале «Покер-клуб «Томь» → Покер-клуб «Томь-Арена»».
4. Снятие владельца: его сессия закрыта, в журнале `owner_dismissed`, второй владелец остаётся.
5. Список клубов с владельцами; у клуба без владельца строка «владельца нет».
   - **Проблема:** при вставке кода через heredoc `"\n"` превратился в настоящий перевод строки, и получилась синтаксическая ошибка.
   - Исправил вручную.
6. Назначение владельцем действующего администратора повышает его до владельца (`outcome: promoted`).
7. Отказы одним параметризованным тестом: сотрудник другого клуба, нет имени, занятое название, не цвет, пустое название, нет такого клуба, не владелец. В каждом случае код выхода 1, причина в stderr, а список клубов не изменился.
   - Сначала случай «не владелец» падал, но ошибка была в самом тесте: в подготовке Анна была владелицей.
   - Взял другой телефон.
   - Проверки названия (пустое, слишком длинное, занятое) и цвета (`#RRGGBB`) добавлены в `league.py`.

После этого прибрал `league.py`: три вида отказа ловятся одним `except`, а телефон форматируется общей функцией журнала.

3. «Убрать»: подтверждение «Убрать из команды: … ? Вход в админ-панель закроется сразу, имя останется в кассе и журнале.», затем сообщение «… больше не в команде». Если нажать «Отмена», ничего не происходит.

## Что сознательно не сделано

- **Переход на экран входа при 401 посреди работы.** Это касается всех страниц админки (так же ведёт себя истёкшая через 7 дней сессия), поэтому лучше сделать отдельной правкой: например, общий обработчик 401 в `api.ts`, который возвращает на вход. Если хотите, оформлю отдельным тикетом.

## Если что-то пошло не так

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Backend не стартует или тесты падают с `column "by_league" … does not exist` | База на промежуточной версии миграции 0015 без этой колонки (только у того, кто запускал незакоммиченную версию) | `docker compose exec db psql -U poker -d poker_test -c "ALTER TABLE action_log ADD COLUMN IF NOT EXISTS by_league boolean NOT NULL DEFAULT false"` (то же для `poker`) |

| Нет раздела «Команда» | Вошли администратором | Войти владельцем (…-11, …-12, …-13) |
| Сотрудник не может войти, кода в логе нет | Владелец убрал его (или лига сняла владельца) | Владелец добавляет телефон снова в «Команде»; владельца — `appoint-owner` |
