## Краткий итог

У каждого турнира появился **«Журнал»**: кто, когда и что сделал, с каким игроком и с какими подробностями. Кнопка «Журнал» есть в каждой строке списка турниров и в шапке страницы «Проведение».

Записи на странице:

- идут **от новых к старым**;
- в каждой есть время по времени клуба, действие, игрок, кто сделал и подробности;
- кто сделал — имя сотрудника или **«игрок»**, если игрок сам записался или отменил запись в боте;
- список **«Игрок»** оставляет записи одного игрока, чтобы восстановить его вечер.

Записи **нельзя изменить или удалить**: в API есть только чтение.

В журнал пишутся все действия, которые уже есть в системе:

| Действие | Пример подробностей |
|---|---|
| Запись на турнир, отмена записи (администратором или в боте) | «Возвращено 2 000 ₽», если игрок уже заплатил |
| Приход, отмена прихода | «2 000 ₽ наличными», «Возвращено 2 000 ₽» |
| Посадка по поздней регистрации | «Стол 2, место 4; 2 000 ₽ картой» |
| Старт | «Игроков: 12, столов: 2» |
| Пауза, продолжение | «Уровень 3, осталось 12:40» |
| Смена уровня | «Уровень 2 → перерыв» |
| Выбывание, отмена выбывания | «Место 7»; «Стол 1, место 4» (куда вернули) |
| Re-entry, add-on | «Стол 1, место 6; 2 000 ₽ наличными»; «1 000 ₽ картой» |
| Пересадка | «Стол 2, место 3 → стол 1, место 5, по подсказке» или «…, вручную» |
| Финальный стол | своя запись у каждого пересаженного игрока: откуда и куда |
| Исправление места | «Место 7 → 4» |
| Сторно, смена способа оплаты | «Операция № 12, add-on 1 000 ₽ наличными»; «Операция № 5, бай-ин 2 000 ₽: наличными → картой» |
| Изменение турнира | только изменённые поля: «Бай-ин: 2 000 ₽ → 2 500 ₽; Структура блайндов» |
| Отмена турнира | «Возвращено 12 000 ₽» |

Тесты: backend **283** (было 269, новых 14 в `test_action_log.py`), frontend **104** (было 100, новых 4 в `ActionLog.test.tsx`; в `Tournaments.test.tsx` в списки кнопок добавлен «Журнал»). mypy и tsc без ошибок.

## Как этим пользоваться

### Запуск

```bash
docker compose up --build          # или docker compose restart backend, если стек уже запущен:
                                   # при старте применится миграция 0013
docker compose exec backend python -m app.demo
```

### Что смотреть в демо

- **«Турбо-серия»** (идёт, «Обь») — самый полный журнал:
  - четверо записались сами в боте, один записался и отменил запись (подпись «игрок»);
  - приходы с оплатой, re-entry, add-on, посадка по поздней регистрации;
  - пересадки по подсказке, выбывания с местом и одно отменённое выбывание.
- **«Кубок новичков»** (через ~3 часа) — пятеро записались в боте, один записался и отменил запись.
- **«Турнир четверга»** — владелец поднял бай-ин: «Изменение турнира · Бай-ин: 2 000 ₽ → 2 500 ₽».
- **«Вечерний кэш-стек»** — сторно и смена способа оплаты; **«Турнир выходного дня»** — исправление места; **«Покерный марафон»** — отмена турнира с возвратом.

Пошаговая ручная проверка — раздел 4.13 «Страница «Журнал» турнира» (пункты Ж1–Ж10) в файле «Функционал системы и ручная проверка».

### Изменения в базе (миграция 0013)

Новая таблица `action_log`:

- `club_id`;
- `tournament_id` — может быть пустым: так будут храниться записи журнала клуба (шаги 15–16);
- `admin_id` — пусто, если действие сделал сам игрок;
- `player_id` — затронутый игрок, может быть пустым;
- `action` — код действия;
- `details` — подробности текстом;
- `created_at`.

Индексы по клубу, турниру и игроку. Старые действия (до миграции) в журнале не видны.

## Решения, принятые с вами до начала работы

1. **Точки тестирования (швы)**, согласованы:
   - HTTP API бэкенда — главная точка;
   - бот через `BotChat`: запись и отмена в боте попадают в журнал как «игрок»;
   - экран «Журнал» через `App` и `fakeBackend`.

   Демо-данные проверены запуском `python -m app.demo`, без отдельного теста.
2. **Незакоммиченные правки CONTEXT.md** из обсуждения спецификации #16 (публичное имя, ник, лист ожидания и т. д.) закоммичены **отдельным коммитом** `531d7ef` до начала работы.

### Решения, которые я принял сам

- **Подробности — готовый русский текст**, записанный в момент действия. Журнал показывает, как было тогда, даже если потом поменяют структуру или цены. Вид действия хранится кодом (`knocked_out`, `moved`…), а русское название вида задаёт фронтенд, как и названия операций кассы.
- **«Создание турнира» в журнал не пишется**: его нет в списке тикета.
- **Пересадка «по подсказке» или «вручную»** определяется так: в момент пересадки система сравнивает её с подсказкой. Совпали игрок и место — значит, «по подсказке».
- **Финальный стол**: по записи на каждого пересаженного игрока, а не одна общая. Тогда фильтр по игроку показывает, куда его пересадили.
- **Изменение турнира** пишется, только если что-то действительно изменилось. Записываются только изменённые поля, структура — одной фразой «Структура блайндов».
- **Исправление места на то же самое место** в журнал не пишется (найдено на ревью).
- **Фильтр по игроку** показывает только записи этого игрока. Общие записи турнира (старт, пауза, смена уровня) в отфильтрованный журнал не попадают.
- **Записи «игрок» в демо.** Настоящего Telegram в демо нет. Поэтому несколько игроков записываются через те же функции бота (`conversation.sign_up` и `drop_out`), но с придуманным и **не сохраняемым** пользователем Telegram. Бот таким пользователям ничего не отправляет.
- **Журнал не обновляется сам** при новых действиях, в отличие от «Регистраций» и «Проведения»: чтобы увидеть новое, откройте его заново. Для разбора споров этого достаточно; при необходимости добавить просто (`useTournamentChanges`).

### Шаг 9. Срезы 7–8: исправление места, сторно и смена способа оплаты

### Шаг 10. Срез 9: правка и отмена турнира — и циклический импорт

Правка и отмена турнира должны были писать в журнал из `tournaments.py`. Но маршрут журнала сам импортировал `club_tournament` из `tournaments.py`, и получался циклический импорт. Решение — разделить модули по образцу кассы:

- запись осталась в `app/action_log.py` (как `transactions.py`);
- чтение вынесено в `app/tournament_log.py` (как `cashier.py`).

### Шаг 11. Фильтр по игроку, доступ, неизменяемость, отказы

Четыре теста:

- **фильтр по игроку.** Сначала красный, затем `?player_id=`.
- **Доступ только к своему клубу.** Администратор другого клуба получает 403 по адресу «Оби» и 404 по адресу своего клуба с чужим турниром.
- **Нет правки и удаления.** `PUT` и `DELETE` записи дают 404, `DELETE` всего журнала — 405.
- **Отклонённое действие ничего не пишет.** Проверены старт с одним игроком (409) и приход без способа оплаты (422).

Эти три теста прошли сразу: их обеспечивают уже существующие проверки клуба и то, что запись идёт после всех проверок. Они фиксируют правила тикета.

### Шаг 15. Ревью кода (`/code-review`)

Два независимых ревьюера: «Стандарты» и «Соответствие тикету».

**Соответствие тикету:** все критерии приёмки выполнены. Найдены:

- **Частично:** «подготовить возможность записи без турнира». Таблица это позволяла, но `record` требовал турнир. **Исправлено:** `record` принимает турнир или клуб.
- Исправление места на то же место писало «Место 3 → 3». **Исправлено по TDD** (новый тест), запись не делается.
- «Назад к списку» в журнале, открытом с «Проведения», ведёт в список, как и у кассы. **Оставлено.**

**Стандарты:** жёстких нарушений нет. Исправлено:

- **повтор форматирования времени лиги** (касса и правка турнира) — общая `league_time_text` в `seasons.py`;
- **повтор разрядов чисел** — `thousands` в `transactions.py`, ею пользуется и `roubles`;
- **повтор «место → место»** в пересадке и финальном столе — `_seat_change`;
- **неудачное имя** `now_playing` рядом с `now` — переименовано в `became`;
- **имена во фронтенде** не совпадали с термином «Action Log» — теперь `ActionLogEntry`, `fetchActionLog`, `actionLogs`;
- **лишний `export`** у `ACTION_NAMES` убран;
- **в тестах** везде константа `ADMIN`, первый тест через общий помощник, порядок импортов.

Оставлено как есть:

- **Длинные вызовы `record(...)` в каждом действии.** ADR-0014 требует, чтобы каждое действие писало свою запись само; общий параметр-объект ради сокращения не добавлял.
- **`PAID_BY` и `roubles` в `transactions.py`.** Это словарь денег, ему место рядом с операциями; отдельный модуль ради двух строк не заводил.

После исправлений полный прогон: **backend 283, frontend 104, mypy и tsc чистые.**

- **Действия до миграции 0013** в журнале не видны.

## Если что-то пошло не так

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Ошибка 500, в логе backend `relation "action_log" does not exist` | Миграция 0013 не применена: backend не перезапускался | `docker compose restart backend` |
| `python -m app.demo` падает с ошибкой внешнего ключа `action_log_tournament_id_fkey` | Запущена старая версия демо-скрипта (без удаления журнала) | Обновить код и запустить снова |
| Журнал турнира пустой, хотя турнир проводили | Турнир проведён до миграции 0013, или база заполнена старым демо | Перезапустить `python -m app.demo` |
| Нет записей с подписью «игрок» | Записи из бота делаются только записью и отменой записи в боте; в демо они есть у «Турбо-серии» и «Кубка новичков» | Записаться в боте на турнир своего клуба |
| В журнале нет только что сделанного действия | Страница журнала не обновляется сама | Нажать «Назад к списку» и снова «Журнал» |
| После выбора игрока не видно старта, паузы и смены уровня | Так задумано: фильтр показывает только записи с этим игроком | Выбрать «Все игроки» |
| Пересадка помечена «вручную», хотя делали как подсказывали | Пересадили того же игрока, но на другое место, чем в подсказке | Ничего: подсказкой считается только точное совпадение игрока и места |
| Время в журнале на 7 часов не то | Браузер или компьютер в другом часовом поясе: время показывается по часам устройства | Поставить на устройстве часовой пояс клуба (UTC+7) |
| Тесты backend падают при подъёме базы с ошибкой про ревизию `0013` | Тестовая база на версии, которой нет в коде (переключение веток) | Вернуться на ветку с кодом 0013, сделать `alembic downgrade 0012` (с `DATABASE_URL` тестовой базы), затем переключиться обратно |
