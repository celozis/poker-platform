## Краткий итог

Администратор клуба ведёт в админ-панели турниры своего клуба. Он может:

- создать турнир;
- взять структуру блайндов из шаблона лиги и поправить её: изменить значения, удалить уровень, добавить уровень, вставить перерыв;
- задать правила re-entry, add-on и поздней регистрации;
- видеть список турниров, разделённый на предстоящие и прошедшие;
- изменить или отменить турнир, пока тот не начался.

Некорректные данные сервер не сохраняет. Он перечисляет все нарушенные правила понятными русскими фразами. Админ одного клуба не видит и не может тронуть турниры другого.

Критерии приёмки из тикета:

| Критерий | Статус | Как проверено |
|---|---|---|
| Администратор создаёт турнир через форму со всеми полями выше | ✅ | Backend-тест создаёт турнир через API и находит его в списке. Frontend-тест заполняет форму и проверяет, что именно ушло на сервер. Вживую в Chrome |
| Есть хотя бы один шаблон структуры блайндов (малый блайнд, большой блайнд, анте, длительность) | ✅ | Два шаблона лиги: «Стандартная» и «Турбо». Backend-тест проверяет поля уровня и то, что из каждого шаблона без правок создаётся корректный турнир |
| Структуру можно поправить перед сохранением: изменить, добавить или удалить уровень, добавить перерыв | ✅ | Backend-тест сохраняет изменённую структуру. Frontend-тест меняет большой блайнд, удаляет уровень, добавляет уровень и перерыв. Ещё один тест проверяет замену структуры другим шаблоном. Вживую в Chrome |
| Список турниров клуба с разделением на предстоящие и прошедшие | ✅ | Backend-тест «двигает часы» и видит, как турниры переходят в прошедшие, с правильной сортировкой. Frontend-тест проверяет оба раздела |

## Как этим пользоваться

```bash
docker compose up --build                          # поднять всё; миграция 0003 применится сама
docker compose exec backend python -m app.seed     # тестовые клубы и админы (если ещё не создавали)
```

Новых npm-пакетов в этом тикете нет, поэтому флаг `-V` из прошлого отчёта не нужен. Но если ваш том `node_modules` старше тикета #3, запускайте с `-V`.

1. Откройте http://localhost:5173 и войдите, как в прошлом тикете: телефон `+7 999 000-00-01` (клуб «Обь») или `+7 999 000-00-02` (клуб «Енисей»). Код смотрите командой `docker compose logs backend | grep "Код входа"`.
2. В панели откроется раздел **«Турниры»**. Нажмите **«Создать турнир»**.
3. Заполните название, начало, бай-ин и стартовый стек. Структура сразу подставится из шаблона «Стандартная лиги». В списке «Шаблон структуры» можно выбрать «Турбо».
4. Правьте таблицу уровней:
   - меняйте числа прямо в ячейках;
   - **«+ перерыв»** в строке уровня вставляет перерыв после этого уровня;
   - **«Удалить»** убирает уровень или перерыв;
   - **«Добавить уровень»** под таблицей добавляет уровень в конец: копию последнего уровня с удвоенными блайндами и анте.
5. Правила: «Re-entry до уровня», «Add-on на уровне», «Поздняя регистрация до уровня». Номера уровней считаются **без перерывов**. **Пустое поле означает, что опция не разрешена.**
6. **«Сохранить турнир»**. Если что-то не так, под формой появится красный блок «Турнир не сохранён» со списком причин. Введённые данные при этом не теряются.
7. В списке у предстоящего турнира есть кнопки **«Изменить»** и **«Отменить турнир»**. Отмена спрашивает подтверждение. Отменённый турнир остаётся в списке, зачёркнутым и с пометкой «Отменён». Кнопок у него больше нет.

### Таблица в базе

| Колонка `tournaments` | Тип | Что хранит |
|---|---|---|
| `id` | integer | номер турнира |
| `club_id` | integer, FK на `clubs`, индекс | клуб-владелец (ADR-0003) |
| `name` | varchar(200) | название |
| `starts_at` | timestamptz | начало. Хранится в UTC, показывается во времени браузера |
| `buy_in` | integer | бай-ин в рублях, 0 допустим (бесплатный турнир) |
| `starting_stack` | integer | стартовый стек в фишках |
| `structure` | JSONB | список уровней и перерывов по порядку (ADR-0004) |
| `reentry_until_level` | integer, может быть NULL | re-entry разрешён до этого уровня включительно. NULL — не разрешён |
| `addon_at_level` | integer, может быть NULL | add-on на этом уровне. NULL — нет add-on |
| `late_registration_until_level` | integer, может быть NULL | поздняя регистрация до этого уровня включительно. NULL — нет |
| `status` | varchar(20) | `scheduled` (запланирован) или `cancelled` (отменён) |

Элемент структуры в JSONB:

```json
{"kind": "level", "small_blind": 100, "big_blind": 200, "ante": 0, "duration_minutes": 20}
{"kind": "break", "duration_minutes": 10}
```

Номер уровня не хранится: он получается из порядка в списке, перерывы не нумеруются.

### Адреса API

Все клубные адреса проходят через `AdminClub` (ADR-0003). Во всех случаях: **401** без входа, **403** «Нет доступа к этому клубу» для чужого клуба.

| Метод и адрес | Что делает | Ответы |
|---|---|---|
| `GET /api/blind-templates` | шаблоны лиги: `[{id, name, structure}]` | **200**. Нужен вход, но не клубный адрес: шаблоны общие для лиги |
| `GET /api/clubs/{club_id}/tournaments` | `{"upcoming": [...], "past": [...]}`. Предстоящие — от ближайшего, прошедшие — от последнего | **200** |
| `POST /api/clubs/{club_id}/tournaments` | создать турнир | **201** турнир, **422** `{"detail": ["сообщение", ...]}` |
| `PUT /api/clubs/{club_id}/tournaments/{id}` | заменить все поля турнира | **200**, **422**, **404** «Турнир не найден» (нет такого у этого клуба), **409** «Турнир уже начался, его нельзя изменить» / «Турнир отменён, его нельзя изменить» |
| `POST /api/clubs/{club_id}/tournaments/{id}/cancel` | отменить | **200**, в том числе повторно для уже отменённого. **404**, **409** «Турнир уже начался, его нельзя отменить» |

**Ошибки 422 всегда приходят списком русских строк** в `detail`. Это касается и ошибок формата во всём API, включая вход: раньше там были английские сообщения FastAPI.

### Правила проверки турнира (`app/tournament_rules.py`)

| Правило | Сообщение |
|---|---|
| Название не пустое (пробелы по краям обрезаются) | «Укажите название турнира» |
| Название не длиннее 200 символов | «Название длиннее 200 символов» |
| Начало в будущем | «Время начала уже прошло» |
| Бай-ин ≥ 0 и помещается в integer PostgreSQL | «Бай-ин не может быть отрицательным» / «Бай-ин слишком большой» |
| Стартовый стек > 0 и помещается в integer | «Стартовый стек должен быть больше нуля» / «Стартовый стек слишком большой» |
| Малый блайнд > 0 | «Уровень N: малый блайнд должен быть больше нуля» |
| Большой блайнд ≥ малого | «Уровень N: большой блайнд не может быть меньше малого» |
| Анте ≥ 0 | «Уровень N: анте не может быть отрицательным» |
| Длительность уровня или перерыва > 0 | «Уровень N: длительность…» / «Перерыв после уровня N: длительность…» / «Перерыв в начале: длительность…» |
| В структуре есть хотя бы один уровень | «В структуре блайндов нет ни одного уровня» (в этом случае правила уровней не проверяются, иначе вышло бы «уровни с 1 по 0») |
| Re-entry, add-on, поздняя регистрация — номер существующего уровня | «Add-on: уровня 12 нет в структуре, в ней уровни с 1 по 3» (так же для «Re-entry» и «Поздняя регистрация») |

Функция возвращает **все** нарушения сразу, а не первое.

Ошибки **формата** ловит FastAPI ещё до этих правил: поле не заполнено, вместо числа текст, дробное число, неизвестный тип строки структуры. Они переводятся в `app/validation_errors.py`, например «Бай-ин: нужно целое число» или «Структура блайндов, строка 3: нужен уровень или перерыв».

### Как части связаны между собой

```
Браузер
  AdminPanel → TournamentsPage
    ├─ GET  /api/clubs/{id}/tournaments        → списки «Предстоящие» / «Прошедшие»
    ├─ «Создать турнир» / «Изменить» → TournamentForm
    │     ├─ GET /api/blind-templates          → список шаблонов, первый подставляется в новый турнир
    │     ├─ StructureEditor (строки хранятся как текст, в числа превращаются при сохранении)
    │     └─ POST или PUT                      → 422/409 → RejectedError → красный блок с причинами
    └─ «Отменить турнир» → window.confirm → POST …/cancel
FastAPI
  app/tournaments.py
    ├─ AdminClub (ADR-0003) → клуб админа; все запросы фильтруются по club.id
    ├─ правка/отмена: строка турнира блокируется (SELECT … FOR UPDATE), затем проверки has_started и статус → 409
    └─ tournament_errors(турнир, now) → 422 со списком сообщений
  app/validation_errors.py → 422 с русскими сообщениями для ошибок формата
PostgreSQL: tournaments (structure в JSONB)
```

«Сейчас» для backend берётся через зависимость `get_now` из `app/auth.py`. Тесты подменяют её управляемыми часами `FakeClock`, так же как в тикете #3.

### Шаг 3. ⚠️ Проблема: вход из фикстуры не находил код в логе

**Симптом.** `AssertionError: No login code for +79130000001 in the log`, хотя в выводе pytest строка «Код входа …» была видна.

**Как искал.**
- Отдельный маленький пробный тест показал, что `caplog` внутри фикстуры обычно работает.
- Отладочный вывод показал, что в фазе подготовки теста `caplog.records` пуст.
- Запуск `test_health.py` вместе с новым файлом: тогда всё проходило. Значит, дело в том, **какой тест в сессии идёт первым**.

**Причина.** Сессионная фикстура `migrated_database` перед первым тестом прогоняет миграции Alembic. `migrations/env.py` при этом вызывает `logging.config.fileConfig(alembic.ini)`, а тот **заменяет обработчики корневого логгера**, в том числе обработчик, которым pytest перехватывает логи на этапе подготовки. В тикете #3 это не проявлялось: там вход всегда был внутри теста, а не в фикстуре. Файл с входом в фикстуре, запущенный первым, падал.

**Исправление** (стандартный приём Alembic):
- `migrations/env.py` вызывает `fileConfig` только если `config.attributes.get("configure_logger", True)`;
- `tests/conftest.py` ставит `config.attributes["configure_logger"] = False`.

Команды `alembic` из консоли и при старте контейнера работают, как раньше. Отладочную строку удалил. После этого тест упал уже по правильной причине: адреса `/api/blind-templates` ещё нет.

### Шаг 4. Backend: первая реализация

По требованию теста написал:

## Известные ограничения и открытые вопросы

1. **Уровень добавляется только в конец структуры.** Перерыв можно вставить после любого уровня, а новый уровень — нет. Чтобы получить уровень в середине, сейчас надо поправить значения соседних. Если нужна вставка, это небольшая доработка `StructureEditor.tsx`: кнопка «+ уровень» в строке, по образцу «+ перерыв».
2. **«Начался» значит «наступило время начала».** Кнопки «начать турнир» и машины состояний (Created → In Progress → …) ещё нет, это следующие тикеты. Когда они появятся, `Tournament.has_started` должен будет учитывать статус. Сейчас, если турнир фактически задержали, после времени начала его уже нельзя поправить.
3. **Часовой пояс.** Время хранится в UTC и показывается в часовом поясе **компьютера администратора**. Если часы или пояс компьютера настроены неверно, время турнира сдвинется. Часового пояса у клуба пока нет. Для клубов в разных поясах (Омск UTC+6, Новосибирск и Красноярск UTC+7) это станет важно, когда турниры начнут смотреть игроки из других городов.
4. **Шаблоны меняются только через релиз**, правкой `backend/app/blind_templates.py` (ADR-0004). Изменение шаблона не влияет на уже созданные турниры: у каждого своя копия структуры.
5. **База не проверяет содержимое JSONB.** Всё держится на проверках API. Запись в `tournaments.structure` в обход API, например вручную через `psql`, может сломать структуру.
6. **Изоляция клубов по-прежнему держится на коде** (ADR-0003). Все новые адреса выполнены по правилам и покрыты тестами на 403.
7. **Русские сообщения об ошибках формата включены для всего API.** Подписи полей лежат в словаре `_FIELDS` в `app/validation_errors.py`. Новые поля в следующих тикетах надо добавлять туда, иначе сообщение будет вида «поле «x»: …».
8. **Гонка правки и отмены закрыта блокировкой строки, но не покрыта тестом.**
9. **Отмену нельзя вернуть.** Отменённый турнир остаётся в списке навсегда, удаления нет. В тикете об этом ничего не сказано.
10. **Прежние хвосты** из тикетов #2 и #3 (флаг `secure` у cookie, очистка старых кодов и сессий, ограничение частоты запросов, раздел «Deployment» в `CLAUDE.md`) остались как были.

## Если что-то сломалось: куда смотреть

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| Backend при старте падает на миграции `0003`, или ошибка `relation "tournaments" does not exist` | Контейнер backend собран до тикета, миграция не применилась | `docker compose up -d --build backend`, в логе должно быть `Running upgrade 0002 -> 0003` |
| Раздел «Турниры» пишет «Не удалось загрузить турниры» | Backend недоступен или вернул ошибку | Строка статуса внизу страницы и `docker compose logs backend` |
| «Время начала уже прошло» при сохранении | Начало в прошлом по часам **сервера** (или неверные часы компьютера) | Проверить дату. Часы сервера: `docker compose exec backend date -u` |
| Время турнира в списке сдвинуто на несколько часов | Часовой пояс компьютера администратора не совпадает с поясом клуба | Проверить пояс в настройках Windows (ограничение 3) |
| «Турнир уже начался, его нельзя изменить/отменить» (409) | Время начала прошло | Так задумано. Прошедшие турниры менять нельзя |
| «Турнир отменён, его нельзя изменить» (409) | Турнир отменён | Создать новый турнир |
| «Add-on: уровня N нет в структуре…» | Номер уровня больше числа уровней, **перерывы не считаются** | Посчитать уровни без перерывов или очистить поле |
| Кнопки «Изменить» нет у турнира | Турнир прошедший или отменён | Так задумано |
| После изменения шаблона в коде старые турниры не изменились | У каждого турнира своя копия структуры (ADR-0004) | Так задумано. Поправить структуру конкретного турнира в форме |
| Ошибки 422 приходят по-английски | Не подключён обработчик `russian_validation_errors` в `app/main.py` | Проверить `app.add_exception_handler(RequestValidationError, …)` |
| Сообщение вида «поле «x»: нужно целое число» | Нового поля нет в `_FIELDS` | Добавить подпись в `app/validation_errors.py` |
| 404 «Турнир не найден» | Турнир принадлежит другому клубу или номер неверен | Проверить `club_id` и номер турнира |
| curl из Git Bash: 400 «There was an error parsing the body» | Кириллица в аргументе командной строки ушла не в UTF-8 | Передавать тело из UTF-8-файла: `--data-binary @file.json` |
| Backend-тесты: «No login code for … in the log» при запуске одного файла | Alembic снова перенастраивает логи в тестах (шаг 3) | Проверить `config.attributes["configure_logger"] = False` в `conftest.py` и условие в `migrations/env.py` |
| Frontend-тесты падают на времени («19:00» не найдено, неверный `starts_at`) | Не задан часовой пояс тестов | Проверить `test.env.TZ` в `vite.config.ts` |
| На телефоне форма шире экрана | Пропал `min-w-0` у `<fieldset>` в `TournamentForm.tsx` | Вернуть `min-w-0` (шаг 13) |
| Тест с `getByLabelText("Шаблон структуры")` не находит список | Подсказка или варианты оказались внутри `<label>` | Подпись связана со списком через `htmlFor="blind-template"` |

## Команды для быстрой проверки

```bash
docker compose up --build                             # поднять всё (миграция 0003 применится сама)
docker compose exec backend python -m app.seed        # тестовые клубы и админы
docker compose logs backend | grep "Код входа"        # коды входа
docker compose run --rm backend pytest                # backend-тесты (38)
docker compose run --rm backend mypy
cd frontend && npm test && npm run typecheck          # frontend-тесты (17)
docker compose exec db psql -U poker -d poker -c "select id, club_id, name, starts_at, status from tournaments"
```
