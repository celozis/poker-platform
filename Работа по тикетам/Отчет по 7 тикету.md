## Краткий итог

Когда турнир заканчивается (выбывает предпоследний игрок), у каждого, кто играл, **фиксируются место и рейтинговые очки**. В админ-панели появилось:

- **Страница «Результаты»** у завершённого турнира: место, игрок, очки, re-entry и add-on. Открывается кнопкой **«Результаты»** в списке «Прошедшие» или кнопкой **«Результаты и исправление мест»** на странице «Проведение» после завершения.
- **Исправление места**: кнопка **«Исправить место»** у игрока → поле «Место» → «Сохранить». Игрок встаёт на новое место, те, кто был между старым и новым местом, сдвигаются на одно. Очки всех пересчитываются, рейтинг клуба тоже.
- **Раздел «Рейтинг»** в меню рядом с «Турниры» и «Игроки»: рейтинг клуба за текущий сезон, по убыванию очков, со столбцами «Место», «Игрок», «Турниров», «Очки». Кнопками **«Предыдущий сезон»** / **«Следующий сезон»** можно посмотреть прошлые сезоны.
- На странице «Проведение» в «Итогах» завершённого турнира теперь видны очки.

**Формула очков по умолчанию:** `очки = 10 × (√(игроков ÷ место) − 1)`, округление до целого. Примеры:

| Игроков | 1 место | 2 место | 3 место | 4 место | 5 место | … последнее |
|---|---|---|---|---|---|---|
| 2 | 4 | 0 | | | | 0 |
| 3 | 7 | 2 | 0 | | | 0 |
| 4 | 10 | 4 | 2 | 0 | | 0 |
| 5 | 12 | 6 | 3 | 1 | 0 | 0 |
| 9 | 20 | 11 | 7 | 5 | 3 | 0 |
| 36 | 50 | … | | | | 0 |

**Сезон** — полугодие: с 1 января по 30 июня и с 1 июля по 31 декабря, граница в полночь по новосибирскому времени (UTC+7). Сейчас идёт «2-е полугодие 2026».

## Как этим пользоваться

```bash
docker compose up --build                          # поднять всё; миграция 0007 применится сама
docker compose exec backend python -m app.seed     # тестовые клубы и админы (если ещё не создавали)
```

Если стек уже запущен, достаточно `docker compose restart backend`: в логе должно появиться `Running upgrade 0006 -> 0007`. Новых npm- и pip-пакетов нет, frontend подхватит изменения сам.

Сценарий для видео:

1. Войдите за «Обь» (`+7 999 000-00-01`), код: `docker compose logs backend | grep "Код входа"`.
2. Создайте турнир (например, «Турбо», re-entry до уровня 2), запишите 5–6 игроков, отметьте приход, на странице «Проведение» нажмите «Начать турнир».
3. Выбейте одного игрока и сделайте ему **Re-entry**, потом выбивайте всех по очереди до последнего. Появится «Турнир завершён» и «Итоги» с местами и **очками**. Покажите, что у игрока с re-entry одна строка.
4. Нажмите **«Результаты и исправление мест»**. Покажите таблицу: место, игрок, очки.
5. У игрока на последнем месте нажмите **«Исправить место»**, введите 2, «Сохранить». Появится «…: 2 место. Очки и рейтинг клуба пересчитаны.», остальные сдвинутся вниз, очки поменяются.
6. «Назад к списку» → в меню **«Рейтинг»**. Видно «2-е полугодие 2026 · 1 июля — 31 декабря 2026» и таблицу по очкам.
7. Сыграйте ещё один короткий турнир (2–3 игрока): очки в рейтинге сложатся, в столбце «Турниров» станет 2.
8. **«Предыдущий сезон»** → «1-е полугодие 2026», там пусто: «В этом сезоне ещё нет завершённых турниров». **«Следующий сезон»** возвращает к текущему.

В рабочей базе после моей проверки остались два завершённых турнира «Проверка итогов» и «Проверка рейтинга» клуба «Обь» (шаг 11–12). Их можно показать на видео или удалить пересозданием базы (`docker compose down -v`, стирает все данные).

### Изменения в базе (миграция 0007)

| Таблица | Колонка / ограничение | Что хранит |
|---|---|---|
| `registrations` | `place` (целое, может быть пустым) | Итоговое место. Заполняется при завершении турнира, меняется при исправлении. Пусто у тех, кто не играл, и пока турнир не завершён |
| `registrations` | `points` (целое, может быть пустым) | Рейтинговые очки за это место |
| `registrations` | `registrations_tournament_id_place_key` | Одно место — один игрок в турнире. Проверяется при фиксации транзакции (`DEFERRABLE INITIALLY DEFERRED`), потому что исправление переставляет несколько мест сразу |

Для турниров, завершённых до миграции, места и очки заполняются из порядка выбывания (`finish_order`) тем же правилом и по той же формуле (SQL-запрос в миграции). Откат (`alembic downgrade 0006`) удаляет колонки и ограничение.

### Адреса API

| Метод и адрес | Что делает |
|---|---|
| `GET /api/clubs/{club}/tournaments/{id}/results` | `{status, results: [{place, player, points, reentries, addons}]}` по местам. Пока турнир не завершён, `results` пустой |
| `PUT /api/clubs/{club}/tournaments/{id}/results/{player}` с `{"place": N}` | Исправляет место, отвечает новыми итогами. Отказы: 409 «Места исправляют после завершения турнира; пока он идёт, отмените выбывание»; 404 «Игрок не играл в этом турнире»; 422 «Место: от 1 до N» |
| `GET /api/clubs/{club}/rating` | Рейтинг текущего сезона: `{season: {id, name, first_day, last_day}, previous_season, next_season, players: [{position, player, points, tournaments}]}` |
| `GET /api/clubs/{club}/rating?season=2026-1` | Рейтинг прошлого сезона. Несуществующий или будущий сезон → 404 «Такого сезона нет» |

Все адреса только для администратора своего клуба (чужой клуб → 403, без входа → 401), как и остальное под `/api/clubs/{club_id}`.

### Правила

- **Место** есть у каждого, кто сидел за столом. Места от 1 до числа игроков, **каждый игрок считается один раз**, сколько бы re-entry он ни сделал. Зарегистрированный, но не пришедший (не севший) игрок места не получает.
- **Очки** = `10 × (√(игроков ÷ место) − 1)`, округление до целого, половина вверх. Последнее место всегда 0.
- **Исправление места**: только в завершённом турнире. Игрок встаёт на новое место, игроки между старым и новым сдвигаются на одно (вверх или вниз). Очки пересчитываются у всех.
- **Рейтинг клуба** = сумма очков игрока в завершённых турнирах **этого клуба** за сезон. Сортировка по очкам, при равенстве по имени. Одинаковые очки делят позицию, следующая позиция считает всех выше: 1, 2, 2, 4. В рейтинге есть и игроки с 0 очков (сыграли, но без очков).
- **Сезон** турнира определяется по **запланированному времени начала** (`starts_at`), по времени UTC+7. Турнир, начатый 31 декабря и законченный после полуночи, остаётся в старом сезоне.

### Как части связаны между собой

```
последнее выбывание ── game.knock_out ── турнир finished
                          │ _places(registrations)  (из порядка выбывания)
                          ▼
                     results.rank(игроки по местам) ── place, points ← points.points(место, игроков)

исправление ── PUT results/{игрок} ── переставить в списке ── results.rank ── commit

рейтинг ── GET rating ── seasons.season_at(сейчас) / season_by_id
                          │
                          ▼
             rating.club_standings(клуб, начало, конец) ── SUM(points) по игрокам ── позиции

проведение (GameState) ── _places: если места зафиксированы, берёт registrations.place
```

### Шаг 2. Решения до начала работы

С вами:

- **Сезоны — полугодия** (январь–июнь и июль–декабрь). Я предлагал «сентябрь–январь и февраль–август» по спеку, вы выбрали полугодия.
- **Точки тестирования (TDD)**: (1) чистая функция формулы очков; (2) чистая функция «в какой сезон попадает момент»; (3) API итогов, исправления и рейтинга, изоляция клубов; (4) интерфейс результатов и рейтинга на подставном сервере.

Мои решения по покерным правилам (вы поручили их мне):

1. **Формула** `10 × (√(игроков ÷ место) − 1)`. Почему: (а) по спеку за первое место «больше всего», за «вылет» 0; (б) по тикету очки зависят и от места, и от числа участников: победа в большом турнире весит больше; (в) при 36 игроках победитель получает ровно 50, как в примере спека; (г) квадратный корень — привычная для клубных лиг форма: очки быстро падают от первых мест к последним, но не обнуляются сразу за призовой зоной. Последнее место всегда 0. Формула простая, её легко объяснить игрокам и администратору.
2. **Участники считаются по одному разу**, re-entry не добавляет участников. Почему: места идут от 1 до числа игроков (так было и в тикете #6), и «последнее место = 0» верно только при таком счёте. Иначе игрок, который делает много re-entry, раздувал бы очки всех остальных. У игрока с re-entry один результат (его последнее место).
3. **Исправление ставит игрока на новое место и сдвигает тех, кто между**, а не меняет двух игроков местами. Почему: типичная ошибка — одно выбывание отметили не вовремя (не того игрока или позже). Сдвиг ровно повторяет то, что было бы при правильной отметке, а остальные сохраняют порядок между собой. Для соседних мест это то же самое, что поменять местами.
4. **Исправлять можно только после завершения.** Пока турнир идёт, для ошибок есть «Отменить выбывание» из тикета #6.
5. **Сезон турнира — по запланированному началу** (`starts_at`), а не по фактическому старту или завершению. Почему: эту дату видят игроки в расписании, она не зависит от того, насколько администратор задержал старт, и турнир попадает ровно в один сезон.
6. **Граница сезона по UTC+7.** Клубы «Обь» (Новосибирск) и «Енисей» (Красноярск) живут в UTC+7 круглый год, своего часового пояса у клубов в системе пока нет.
7. **Одинаковые очки делят позицию** в рейтинге (1, 2, 2, 4), в порядке по имени.

Сам добавил, хотя тикет прямо не просил:

- **Просмотр прошлых сезонов.** Иначе 1 июля рейтинг обнулится, и администратор не сможет подвести итоги ушедшего сезона.
- Столбец **«Турниров»** в рейтинге и **очки в «Итогах»** на странице проведения.

### Шаг 3. Формула очков (TDD, точка 1)

Написал тест «победитель из 36 игроков получает 50» → красный (модуля нет). Написал `app/points.py`. Функция сразу получилась целиком, с проверкой места вне поля, поэтому следующие тесты (последнее место = 0 при 2, 9, 36, 120 игроках; все места поля из 9: 20, 11, 7, 5, 3, 2, 1, 1, 0; поля из 2 и 3; монотонность для полей 2…100; ошибка на месте 0 и 6 из 5) прошли сразу. Ожидаемые значения я посчитал вручную, а не той же формулой в тесте.

Округление: `floor(x + 0.5)`, а не `round()`. В Python `round(2.5) = 2` («банковское» округление), а игрокам привычнее «половина вверх».
